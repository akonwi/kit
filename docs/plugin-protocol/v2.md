# Kit plugin protocol version 2

This is the normative specification of Kit plugin protocol version 2
([ADR 0065](../adrs/0065-stabilize-the-plugin-protocol-as-version-2.md)). It
describes exactly what Kit implements. A plugin written to it needs nothing
else.

The [protocol schema](v2/protocol.schema.json) and
[manifest schema](v2/manifest.schema.json) are generated from the Go package
[`api/pluginprotocol`](../../api/pluginprotocol) and describe every message,
params object, result, and manifest member. Where this document and a schema
both state a rule, they agree. A message the schema rejects, Kit rejects too,
but some messages the schema accepts Kit still rejects: Kit counts lengths
in UTF-8 bytes where the schema counts characters, checks format characters
outside the Basic Multilingual Plane, bounds encoded params, and canonicalizes
URLs. This document states those rules and others a schema cannot, such as
ordering.

The key words **MUST**, **MUST NOT**, **SHOULD**, and **MAY** are used as in
RFC 2119.

## Overview

A plugin is a program that Kit starts for a session and speaks to with
JSON-RPC 2.0 over the plugin's stdin and stdout. Plugins contribute commands,
model tools, a tool-call interceptor, subagent definitions, and footer items;
ask the user questions; show notifications; start turns in their session; ask
clients to open web pages; and receive session, Git, and turn events.

Kit runs plugins on the machine where the Kit server runs, as the same user.
A plugin is trusted code, not a sandbox: it can read and write anything that
user can. The pipe identifies the plugin, so it needs no credential, address,
or network access to reach Kit. Users MUST only install plugins, or open
projects containing plugins, they trust.

## Installation and manifest

Kit discovers plugins in two places, in this order:

1. user plugins: `~/.kit/plugins/*/plugin.json` (the Kit home is `KIT_HOME`
   when set);
2. project plugins: `<session cwd>/.kit/plugins/*/plugin.json`.

Each `*` is one immediate child directory, followed if it is a symbolic link
to a directory. Within each place Kit sorts installations by directory name.
The directory name is a label; the manifest's `id` is the plugin's identity.
When two manifests claim one ID, the first in discovery order wins and the
other does not start; Kit reports a diagnostic naming both paths. Kit plans at
most 128 installations per session.

`plugin.json` is a JSON object of at most 1 MiB:

```json
{
  "$schema": "https://raw.githubusercontent.com/akonwi/kit/main/docs/plugin-protocol/v2/manifest.schema.json",
  "manifestVersion": 1,
  "protocolVersion": 2,
  "id": "speech",
  "name": "Speech",
  "transport": { "type": "stdio", "command": "python3", "args": ["-u", "plugin.py"] }
}
```

| Member | Rule |
| --- | --- |
| `$schema` | Optional absolute URI, for editors. Kit does not fetch it. |
| `manifestVersion` | `1`. |
| `protocolVersion` | `2`. A manifest without it speaks protocol version 1, which is [specified separately](v1.md) and will be removed; see the [migration guide](migrating-from-v1.md). |
| `id` | `^[a-z][a-z0-9-]*$`, at most 32 characters, not `kit`, not beginning with `kit-`, and not a Kit command domain. |
| `name` | Optional display name, 1 to 128 characters. |
| `transport.type` | `stdio`. |
| `transport.command` | The program. A bare name is found on `PATH`; a name containing a path separator is relative to the manifest's directory. |
| `transport.args` | Optional arguments, passed literally. |

Unknown members, and `null` for any member, make the manifest invalid. Kit
starts the command without a shell, with the manifest's directory as its
working directory and Kit's environment. Kit does not install dependencies;
the command MUST already run.

## Transport

Kit writes messages to the plugin's stdin and reads them from its stdout. Each
message is one JSON-RPC 2.0 object encoded as UTF-8 on one line ending in
`\n`; Kit also accepts `\r\n` and ignores empty lines. A line carries exactly
one object: version 2 has no batches. Kit answers an array with `-32600` and a
null `id`, processes none of its members, and keeps serving.

The plugin MUST write only protocol messages to stdout. Diagnostics go to
stderr; Kit keeps the last 64 KiB. Anything on stdout that is not valid JSON,
or not a valid JSON-RPC message, makes Kit answer with an error when it can and
then stop the plugin as failed.

Both sides read continuously while their own requests are pending: requests
may run concurrently, may nest in either direction, and may be answered in any
order. Each side MUST serialize its writes so lines do not interleave.

Request IDs are strings or integers, unique among the sender's outstanding
requests; the two directions have independent ID spaces. Kit's IDs are strings
such as `kit-12`. Params are always an object; a method without params omits
`params`. Method names beginning with `rpc.` are reserved.

| Transport bound | Value |
| --- | --- |
| Line length before the newline | 16 MiB |
| Kit's queued output to one plugin | 32 MiB; a plugin that stops reading is stopped |
| Plugin requests Kit runs at once | 128; more are answered `-32006` with `data.reason` `busy` |
| Kit requests pending to one plugin | 128 |
| Queued plugin notifications | 128; flooding stops the plugin |

## Lifecycle

### Initialization

Kit starts plugins in discovery order and initializes them one at a time in
the background. Turns do not wait for plugins: early model requests may lack
plugin tools, interceptors, or subagents.

Kit's first message is `initialize`:

```json
{
  "jsonrpc": "2.0",
  "id": "kit-1",
  "method": "initialize",
  "params": {
    "protocolVersion": 2,
    "kit": { "version": "0.58.0" },
    "instance": { "id": "pluginhost_…:1" },
    "context": {
      "project": {
        "cwd": "/home/me/project",
        "git": { "root": "/home/me/project", "branch": "main", "dirty": false, "pullRequest": null }
      },
      "session": { "id": "session_…", "name": "Plugin protocol" }
    },
    "status": { "sessionId": "session_…", "model": "anthropic/claude-sonnet-4-5", "…": "…" }
  }
}
```

- `kit.version` is the server's version, for diagnostics.
- `instance.id` identifies this generation of the plugin in this session. It
  is opaque. Clients see the same identifier on the plugin's toasts, dialogs,
  footer items, and commands. A replacement generation gets a new one.
- `context` is the [session and project](#context-and-events).
- `status` is the session's [status](#session-status) when the instance
  starts. It is optional: a Kit release before session status does not send
  it.

The plugin answers `{ "protocolVersion": 2 }` within 10 seconds. Any other
answer, an error, a timeout, an exit, or a request or notification sent before
the answer fails the instance. Once Kit receives the answer the instance is
*ready* and may send requests.

### Shutdown

Kit stops a ready instance when the session is reloaded or unloaded, when the
server stops, and, for project plugins, when the session's cwd changes. Kit
first stops accepting the instance's requests (they fail with `-32002`),
removes its contributions, and cancels its pending work in both directions.
It then sends `shutdown`, which has no params. The plugin answers `null` and
exits. Kit allows two seconds, then sends `SIGTERM` to the plugin's process
group, and `SIGKILL` two seconds later. Kit starts each plugin in its own
process group, so the plugin's child processes stop with it. A plugin SHOULD
also exit when stdin reaches end of file.

### Failure

An exit Kit did not ask for, including exit status zero, is a crash. Kit
removes the instance's contributions, fails its pending calls, sends a
persistent failure notification to the session's clients, and writes a summary
and the stderr tail to the server log. Malformed output, an invalid result,
answering an unknown request, and exceeding a transport bound fail the
instance the same way. Kit does not restart failed plugins; reloading the
session starts a new generation.

### Scope

Each session runs its own instance of each plugin. An instance keeps running
while its session is loaded, whether or not clients are attached.

- A rename sends `kit/events/session.changed`.
- A cwd change keeps user plugins running and sends them
  `kit/events/project.changed`; project plugins are stopped and the new cwd's
  project plugins are started.
- A session reload stops every instance and starts new generations.

A generation's contributions, pending dialogs, and calls belong to it. A
stopped or replaced generation cannot answer or change anything, and Kit never
sends an old generation's calls to its replacement. Stopping a plugin does not
undo effects it already performed.

## Contributions and identifiers

Commands, subagents, and footer items have local IDs: one or more
dot-separated segments of `^[a-z][a-z0-9-]*$`, at most 128 bytes. Tools have
local IDs matching `^[a-z][a-z0-9_]*$`, at most 64 bytes. Kit prefixes the
plugin ID to form the canonical ID: plugin `speech`'s command `settings.open`
is `speech.settings.open`. A tool's model-facing name is `<plugin>__<tool>`,
such as `speech__speak`, and is at most 64 characters.

Kit sends plugins local IDs. Registering a command, tool, or subagent ID the
plugin already registered fails with `-32003`; removing an unknown ID
succeeds. Registrations take effect
immediately: commands and footer items reach clients at once, and tools,
interceptors, and subagents apply from the next model request or tool call. A
request already sent to the model keeps the catalog it was sent with.

Text members described as *single-line* reject control and Unicode format
characters; *multiline* text also allows newline and tab. All lengths are
UTF-8 bytes. Every registration's params are at most 64 KiB encoded.

Optional text members MAY be `null`, which means absent. Other optional
members, such as booleans, arrays, and `parentId`, are omitted when absent.

## Commands

### `kit/commands/register` (plugin request)

```json
{ "id": "toggle", "description": "Toggle spoken responses", "argName": "on|off", "category": "Speech" }
```

`description` is required, single-line, at most 1,024 bytes. `argName` and
`category` are optional, single-line, at most 128 bytes. The result is
`{ "id": "<canonical ID>" }`. A session holds at most 256 commands.

Clients list the command under its canonical ID with the plugin as its
owner.

### `kit/commands/unregister` (plugin request)

Params `{ "id": "toggle" }`; result `null`.

### `kit/commands/execute` (Kit request)

```json
{ "id": "toggle", "args": "on" }
```

A user invoked the command. `args` is the literal text after it, or the empty
string, at most 64 KiB. The plugin answers `null`, or an error whose message
Kit shows the user. Commands do not start a turn or change the user's draft.
Kit cancels the request if the user abandons it; a client waits at most two
minutes.

## Tools

### `kit/tools/register` (plugin request)

```json
{
  "id": "speak",
  "label": "Speak",
  "description": "Speak text aloud",
  "inputSchema": {
    "type": "object",
    "properties": { "text": { "type": "string" } },
    "required": ["text"],
    "additionalProperties": false
  },
  "executionMode": "sequential",
  "promptSnippet": "Use speech__speak to read results aloud.",
  "promptGuidelines": ["Keep spoken text short."]
}
```

| Member | Rule |
| --- | --- |
| `id` | Required local tool ID. |
| `label` | Optional, single-line, at most 512 bytes; defaults to `id`. |
| `description` | Required, multiline, at most 8 KiB. |
| `inputSchema` | Required; see below. |
| `executionMode` | `sequential` (default) or `parallel`: whether the tool's calls may run alongside other calls from the same model response. |
| `promptSnippet` | Optional, multiline, at most 8 KiB, added to the system prompt with the tool. |
| `promptGuidelines` | Optional, at most 32 multiline strings of at most 1 KiB each. |

The result is `{ "id": "<canonical ID>", "modelName": "<plugin>__<tool>" }`.
A session holds at most 128 tools.

`inputSchema` uses this subset of JSON Schema draft 2020-12. The root is an
object whose `type` is `"object"`. Every schema, including the root, may use
only: `$schema` (`https://json-schema.org/draft/2020-12/schema`), `type`
(`object`, `array`, `string`, `number`, `integer`, `boolean`, `null`),
`description`, `properties`, `required`, `additionalProperties` (a boolean),
`items`, `enum`, `const`, `anyOf`, `minimum`, `maximum`, `exclusiveMinimum`,
`exclusiveMaximum`, `minLength`, `maxLength`, `pattern`, `minItems`, and
`maxItems`. Patterns use Go's RE2 syntax. A schema has at most 1,024 nodes and
16 levels and cannot reference other schemas. Kit rejects any other schema
with `-32602`.

### `kit/tools/unregister` (plugin request)

Params `{ "id": "speak" }`; result `null`.

### `kit/tools/execute` (Kit request)

```json
{ "id": "speak", "toolCallId": "call_…", "input": { "text": "Done" } }
```

The model called the tool. Kit has validated `input` against the tool's
schema exactly, without defaults or coercion, and bounded it to 64 KiB; numbers
keep their exact JSON text. The plugin answers:

```json
{
  "content": [
    { "type": "text", "text": "Spoke the requested text." },
    { "type": "image", "data": "<base64>", "mimeType": "image/png" }
  ],
  "details": { "characters": 25 },
  "terminate": false
}
```

- `content`: at most 64 parts, text or base64 PNG, JPEG, GIF, or WebP images,
  at most 4 MiB of decoded content in total. The model sees the content; Kit
  keeps images as session attachments.
- `details`: optional JSON, at most 64 KiB, kept with the call but not sent to
  the model.
- `terminate`: optional; `true` ends the turn after the current batch of tool
  calls completes.

An error answer becomes a failed tool result, and the model sees its
message. Plugins SHOULD use `-32000`. An invalid result fails the instance. Kit cancels the request when
the turn is aborted. There is no timeout and no progress reporting.

## Tool-call interception

### `kit/tool-calls/register-interceptor` and `kit/tool-calls/unregister-interceptor` (plugin requests)

No params; result `null`; both idempotent. An instance has at most one
interceptor, a session at most 128.

### `kit/tool-calls/before-execute` (Kit request)

```json
{ "toolCall": { "id": "call_…", "name": "bash", "input": { "command": "npm publish" } } }
```

Before every tool call, core or plugin, including those of the session's
subagents, Kit asks each interceptor in registration order. `name` is the
model-facing tool name. `input` is at most 1 MiB. Separate tool calls may be
intercepted concurrently. The plugin answers one of:

```json
{ "action": "allow" }
```

```json
{ "action": "reject-and-continue", "message": "The user rejected this command." }
```

Only `allow` lets the next interceptor, and then the tool, run. The first
rejection blocks the call and gives the model `message` (at most 8 KiB) as its
result. An error, a cancellation, a stopped instance, or an invalid answer
blocks the call; an invalid answer also fails the instance. Kit cancels the
request when the turn is aborted. Once an interceptor is gone, later calls run
without it.

Interceptors typically ask the user with `kit/ui/confirm`, naming the
`before-execute` request as the dialog's [`parentId`](#nested-requests).

## Subagents

### `kit/subagents/register` (plugin request)

```json
{ "id": "reviewer", "description": "Review code changes", "instructions": "Inspect the change and report findings.", "model": null }
```

`description` is required, single-line, at most 1,024 bytes. `instructions`
are required, multiline, at most 128 KiB. `model` is an optional Kit model
selector of at most 256 bytes; without it the subagent uses the session's
model. The result is `{ "id": "<plugin>.<id>" }`, the name the model uses.

Kit runs the subagent; the plugin only defines it. A definition from the
user's or project's subagent files with the same name takes precedence:
registering it fails with `-32003`. The session's catalog holds at most 128
definitions.

### `kit/subagents/unregister` (plugin request)

Params `{ "id": "reviewer" }`; result `null`. Removing a definition stops new
subagents from using it; subagents already running continue.

## Footer

Plugins add items to the bottom-right of the session footer, beside Kit's cwd
and Git item, `kit.footer.location`.

### `kit/footer/set` (plugin request)

```json
{
  "id": "status",
  "content": [
    { "text": "speech " },
    { "text": "on", "style": { "fg": "toolText", "bold": true } }
  ]
}
```

Creates or replaces the item; replacing keeps its position. `content` holds 1
to 32 segments of single-line text, at most 4 KiB in total. `style` may set
`fg` and `bg` to a [theme token](#theme-tokens) and `bold`, `dim`, `italic`,
`underline`, and `strikethrough` to booleans. The result is
`{ "id": "<canonical ID>" }`. A session holds at most 64 items.

### `kit/footer/clear` (plugin request)

Params `{ "id": "status" }`; result `null`.

### `kit/footer/hide` and `kit/footer/show` (plugin requests)

Params `{ "id": "<canonical ID>" }`, naming `kit.footer.location` or any
plugin's footer item, including one that does not exist yet. `hide` adds the
plugin's claim; `show` withdraws only the plugin's own claim. An item is hidden
while any plugin claims it. A session holds at most 256 claims. Result `null`.

When a generation stops, its items and claims go with it.

## Dialogs

Dialogs ask the user a question in every client attached to the session. The
first answer from any client wins. A dialog stays pending while no client is
attached, including in `kit print`, until a client answers it or it is
cancelled. A session has at most eight pending plugin dialogs; more fail
with `-32005`.

### `kit/ui/confirm` (plugin request)

`title` is required, single-line, at most 512 bytes. Optional: `message`
(multiline Markdown, at most 8 KiB), `confirmLabel` and `cancelLabel` (at most
128 bytes), `defaultValue` (the answer focused initially), and `parentId`. The
result is `true`, or `false` when the user declines or dismisses it.

### `kit/ui/input` (plugin request)

`title` as above. Optional: `message`, `placeholder` (at most 512 bytes),
`initialValue` (at most 16 KiB), and `parentId`. The result is the entered text
(at most 16 KiB; the empty string is an answer) or `null` when dismissed.

### `kit/ui/select` (plugin request)

```json
{
  "title": "Choose target",
  "options": [
    { "label": "Current file", "value": { "kind": "file" }, "description": "Use the active file" },
    { "label": "Nothing", "value": null }
  ],
  "placeholder": "Filter targets"
}
```

`title` as above; `options` holds 1 to 64 options. Each has a single-line
`label` of at most 512 bytes, a required `value` of any JSON of at most 16 KiB,
and an optional `description` of at most 8 KiB. Optional: `message`,
`placeholder`, and `parentId`. The result is `{ "value": <the chosen value> }`,
exactly as sent, or `null` when dismissed. Kit never sends option values to
clients.

When Kit has no way to show dialogs it answers `-32000` with `data.reason`
`interactivity_unavailable`. Cancellation and failure are never an answer: a
cancelled dialog answers `-32001`, and a stopped instance's dialogs end.

### Nested requests

A dialog MAY name, with `parentId`, the `id` of a Kit request the plugin is
still handling, such as the `kit/tool-calls/before-execute` an approval belongs
to or the `kit/commands/execute` that asked. When that request ends, because
the plugin answered it, Kit cancelled it, or the instance stopped, Kit cancels
the dialog, which answers `-32001`. A `parentId` that names no pending Kit
request cancels the dialog at once. Plugins MAY still cancel their own dialogs
with `kit/cancel`.

## Notifications

### `kit/ui/toast` (plugin notification)

```json
{ "title": "Speech enabled", "subtitle": null, "variant": "info", "persistent": false }
```

`title` is required, single-line, at most 1,024 bytes. `subtitle` is
optional, multiline, at most 4,096 bytes. `variant` is `info`, `warning`, or
`error`. `persistent` keeps the notification until the user dismisses it and
also records it in the session's diagnostics. Clients attached at that moment
show it; it is never replayed. Kit ignores an invalid toast.

## Session

### `kit/session/submit-message` (plugin request)

```json
{ "text": "Review the current working tree.", "idempotencyKey": "loop-7" }
```

Starts a turn in the plugin's own session with a message attributed to the
plugin ([ADR 0041](../adrs/0041-let-plugins-submit-session-messages.md)).
`text` is required, not blank, at most 128 KiB. `idempotencyKey` is optional,
1 to 128 characters of `A-Z a-z 0-9 . _ : -`: repeating a key with the same
text returns the original result, even after a reload or restart, and with
different text fails with `-32003`.

The result, once the turn is admitted, is `{ "messageId": "…", "turnId": "…" }`.
Kit admits a message only when the session can start a turn immediately; when
a turn is running, user follow-ups are queued, or the session is changing, it
answers `-32006` with `data.reason` `session_busy` and records nothing. Kit
does not queue or retry messages. A plugin MAY submit from its
`kit/events/agent.turn.completed` handler.

### Session status

A session's status is its model configuration, context use, and cumulative
usage and cost, the values clients show in their debug views
([ADR 0066](../adrs/0066-share-session-status-with-plugins.md)):

```json
{
  "sessionId": "session_…",
  "model": "anthropic/claude-sonnet-4-5",
  "thinkingLevel": "medium",
  "parent": { "id": "session_…", "name": "Building Kit" },
  "context": { "tokens": 48210, "window": 200000 },
  "usage": {
    "input": 812345, "output": 40211, "cacheRead": 700000, "cacheWrite": 52000,
    "reasoning": 9000, "totalTokens": 1613556,
    "cost": { "input": 2.44, "output": 0.6, "cacheRead": 0.21, "cacheWrite": 0.2, "total": 3.45 }
  }
}
```

| Member | Meaning |
| --- | --- |
| `sessionId` | The instance's session. |
| `model` | The `provider/id` model selector. |
| `thinkingLevel` | The applied thinking level. |
| `parent` | `{ id, name }` of the session this one was started from, such as a subagent's parent, or `null`. `name` is `null` when the parent has none. |
| `context` | `{ tokens, window }`: the estimated input of the latest model request and the model's context window, or `null` before Kit knows the window. |
| `usage` | Cumulative provider usage and cost in US dollars for this session only. A subagent is its own session with its own status. |

Kit sends the status in `initialize`, sends
`kit/events/session.status.changed` when it changes, and answers
`kit/session/status`. Usage and context change with every model response, so
status notifications are coalesced: an instance has at most one queued, and a
newer status replaces a queued one Kit has not yet written. A plugin always
ends with the current status, but may not see every intermediate one, and a
status notification may arrive after the turn event of the same response.

### `kit/session/status` (plugin request)

Takes no params and returns the latest [status](#session-status). A Kit
release before session status answers `-32601`.

### `kit/system/open-url` (plugin request)

```json
{ "url": "https://example.com/docs" }
```

Asks the clients attached to the plugin's session to open a web page
([ADR 0049](../adrs/0049-let-plugins-ask-attached-clients-to-open-web-pages.md)).
The URL is an absolute `http` or `https` URL with a host, without credentials,
whitespace, or control characters, at most 2 KiB; params are at most 8 KiB.
The result `null` means Kit published the request; it does not report whether
any client opened the page. More than five requests from the session's plugins
within ten seconds fail with `-32006` and `data.reason` `rate_limited`.

## Context and events

Kit sends events as notifications to every ready instance, in order, without
waiting for acknowledgement. Plugins do not subscribe; they ignore events they
do not need. Events are live: a later generation does not receive earlier ones.

The context in `initialize` has the session (`id`, nullable `name`) and the
project:

| Member | Meaning |
| --- | --- |
| `cwd` | Absolute working directory. |
| `git` | `null` outside a Git worktree or when Git cannot be inspected safely. |
| `git.root` | Absolute worktree root. |
| `git.branch` | Branch name, or `null` for a detached head. |
| `git.dirty` | Whether the worktree has changes. |
| `git.pullRequest` | `{ number, url, checks? }` for the branch's GitHub pull request, or `null` when there is none or it is not known yet. |
| `git.pullRequest.checks` | `{ state, required, counts, items, omitted }`: `state` is `failing`, `pending`, `passing`, or `none`; `required` is `satisfied`, `unsatisfied`, `pending`, or `unknown`; `counts` counts every check by state; `items` lists at most 50 checks, failing first, and `omitted` counts the rest ([ADR 0060](../adrs/0060-share-observed-pull-request-checks-with-clients-and-plugins.md)). |

| Notification | Params | When |
| --- | --- | --- |
| `kit/events/session.changed` | the session | The session was renamed. |
| `kit/events/project.changed` | the project | The cwd changed; sent to user plugins only, before any `git.changed` for the new cwd. |
| `kit/events/git.changed` | `{ "git": … }` | Git state or the pull request changed. Kit checks every ten seconds and when it observes changes; intermediate states may be skipped. Pull request lookups use the user's `gh` login and never delay local Git state. |
| `kit/events/agent.turn.started` | `{ sessionId, turnId }` | Kit admitted a turn, before model or tool work. |
| `kit/events/agent.turn.completed` | `{ sessionId, turn: { id, messages } }` | The turn settled, whether it completed, failed, or was aborted. |
| `kit/events/session.status.changed` | the [status](#session-status) | Any status member changed; coalesced. |
| `kit/events/compaction.started` | `{ sessionId, compactionId, turnId }` | The session started compacting its conversation. `turnId` is `null` outside a turn, as when a client asked for compaction. |
| `kit/events/compaction.completed` | `{ sessionId, compactionId, turnId, failureReason }` | The compaction ended. `failureReason` is `null` on success, otherwise `summary_truncated`, `summary_invalid`, `policy_stop`, `provider_error`, `not_adaptable`, `canceled`, `conflict`, or `internal_error`. |

`messages` holds the turn's user and assistant messages in order, each
`{ role, content }` with only `{ "type": "text", text }` parts: thinking, tool
calls and results, images, and metadata are left out. Only instances that
received a turn's start receive its completion. An event that would exceed
256 KiB, or that Kit cannot project within its time limit, is omitted rather
than truncated, so a start is not always followed by a completion. Recovered
or interrupted turns from before a restart send no events.

Compaction events are likewise best effort: Kit may omit them when an
instance cannot keep up, so a `compaction.started` is not always followed by
a `compaction.completed`. Status is never omitted; the latest status always
arrives.

## Cancellation

Either side cancels a request it sent with the notification `kit/cancel`,
params `{ "id": <request ID> }`. Cancelling an unknown or finished request does
nothing.

- When Kit cancels, it ignores any later answer. The plugin SHOULD stop the
  work.
- When the plugin cancels a request to Kit, Kit answers it with `-32001` and
  stops the work. A request Kit has already completed is unaffected.

Cancellation is not rollback: work may have partly happened. Kit imposes no
timeout on commands, tools, interceptors, or dialogs beyond initialization and
shutdown.

## Errors

Error objects have an integer `code`, a concise `message` safe to show users,
and optional structured `data`. Errors from Kit put a `reason` in `data` where
listed below.

| Code | Meaning |
| ---: | --- |
| `-32700` | The line is not valid JSON or UTF-8. |
| `-32600` | Not a valid request, including a batch. |
| `-32601` | Unknown method. |
| `-32602` | Invalid params; the message names the rule broken. |
| `-32603` | Internal error. |
| `-32000` | A command or tool failed; or, with `data.reason` `interactivity_unavailable`, Kit cannot show dialogs. |
| `-32001` | Cancelled. |
| `-32002` | The instance's generation is stopping, stopped, or replaced. |
| `-32003` | Conflict: a duplicate contribution, or an idempotency key reused with different text. |
| `-32005` | A size or count limit was exceeded. |
| `-32006` | Try again later. `data.reason` is `busy` (too many requests in flight), `session_busy` (submit-message), or `rate_limited` (open-url). |

Every plugin request can fail with `-32602`, `-32603`, `-32001`, `-32002`,
and `-32006`. Some can also fail with these codes:

| Plugin request | Further codes |
| --- | --- |
| `kit/commands/register`, `kit/tools/register`, `kit/subagents/register` | `-32003`, `-32005` |
| `kit/ui/confirm`, `kit/ui/input`, `kit/ui/select` | `-32000`, `-32005` |
| `kit/session/submit-message` | `-32003`, `-32005` |
| `kit/tool-calls/unregister-interceptor`, `kit/session/status` | none |
| every other plugin request | `-32005` |

A plugin answers Kit's `kit/commands/execute`, `kit/tools/execute`, and
`kit/tool-calls/before-execute` requests with `-32000` when its handler fails
and `-32001` when Kit cancelled the request. The same lists appear under
`x-kit-methods` in the [protocol schema](v2/protocol.schema.json).

## Compatibility

Within version 2, Kit may add optional members to objects it sends, add
notifications it sends, and add plugin-to-Kit methods and optional params.
Plugins MUST ignore members and notifications they do not know. The protocol
schema describes objects Kit sends as open and objects plugins send as closed,
so a validator written against an earlier version 2 schema accepts newer Kit
messages.

Removing or renaming anything, adding a required member, tightening a shape or
bound, changing a result or error, or adding a Kit-to-plugin request requires a
new protocol version, with its own specification and schema directory. See
[docs/plugin-development.md](../plugin-development.md).
