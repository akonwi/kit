Kit 0.36.0 rebuilds the coding agent around a native Go executable and a new
terminal UI. Kit itself no longer requires Bun or Node.js. Plugins and MCP servers
may still require their own runtimes.

## What's changed

This is a runtime replacement, not just a visual refresh:

- **New terminal UI:** vaxis replaces OpenTUI, with Tree-sitter highlighting
  compiled into the executable. This is not complete feature or UI parity with
  0.35.x; browser and desktop clients are not included in the release archives.
- **Server-owned sessions:** Kit automatically starts or discovers its local
  server. Sessions use SQLite-backed state, and `kit` resumes the latest usable
  session for your directory. Legacy sessions do not carry over.
- **Interactive and headless workflows:** use the TUI for ongoing work or
  `kit print` for one turn, with final assistant prose on stdout and diagnostics
  on stderr.
- **Concurrent subagents:** delegated work runs as supervised child executions
  with durable conversations and mailboxes.
- **Language-neutral plugins:** extensions run as JSON-RPC child processes rather
  than importing the TypeScript runtime or rendering directly into its UI.
- **Native distribution:** Homebrew and downloadable binaries replace npm.

## Getting started

Enter your project directory and run `kit`. If credentials are missing, the TUI
provides login options for OpenAI, Anthropic, and OpenCode Go API keys, plus OpenAI
Codex and Claude Pro/Max subscription login. Model availability depends on your
provider access.

```sh
kit                                  # Resume this directory's latest session
kit new --name "Implement search"     # Create a saved session
kit sessions                         # Browse saved sessions
kit --session <session-id>            # Open a long or short session ID
kit --temp                           # Discard temporary state on foreground exit
kit print "Summarize this project"    # Run one headless turn
git diff | kit print --temp "Review this diff"
kit server status
kit --help
```

Use `/model`, `/settings`, and `/reload` in the TUI command palette. Reload
refreshes runtime configuration and cancels in-flight plugin work. For Codex
headless device login, use `kit auth login openai-codex` and `kit auth status`.
Provider environment variables take precedence over stored credentials and are
captured at server startup; run `kit server restart` after changing them, when
interrupting active work is acceptable.

## Installation and upgrade

Back up your Kit home before upgrading. It defaults to `~/.kit`; `KIT_HOME`
overrides it. Remove an old npm installation with:

```sh
npm uninstall -g @akonwi/kit
```

Once the Homebrew formula is updated for this release:

```sh
brew install akonwi/tap/kit
# Or, for an existing Homebrew installation:
brew update && brew upgrade akonwi/tap/kit
```

For manual installation, download the archive matching your OS and architecture
from this release, extract it, and place `kit` in a directory on PATH. For example,
using the macOS Apple Silicon archive downloaded into the current directory:

```sh
tar -xzf kit_v0.36.0_darwin_arm64.tar.gz
mkdir -p "$HOME/.local/bin"
install -m 755 kit "$HOME/.local/bin/kit"
export PATH="$HOME/.local/bin:$PATH"
command -v kit
kit version
```

Persist the PATH change in your shell configuration if needed. Verify the version
is `0.36.0`; an earlier Homebrew, npm, or manually installed binary may otherwise
win PATH resolution. Keep Node.js or other interpreters if your extensions need them.

Archives contain only `kit`, with no separate `runtime` directory:

- `kit_v0.36.0_darwin_arm64.tar.gz`
- `kit_v0.36.0_darwin_amd64.tar.gz`
- `kit_v0.36.0_linux_arm64.tar.gz`
- `kit_v0.36.0_linux_amd64.tar.gz`

macOS targets version 14 or newer. Linux binaries are built on Ubuntu 24.04 with a
**glibc 2.39 baseline**; they are not fully static and older libc compatibility is
not guaranteed. Windows is unsupported.

## Migration: important compatibility changes

- **Start fresh sessions.** There is no legacy session import or automatic
  configuration/credential converter. Do not delete old runtime data to upgrade.
- **Reauthenticate as needed.** Use supported provider and MCP login flows rather
  than rewriting authentication-cache internals.
- **Review settings.** Preserved JSON fields are not necessarily active settings.
  User-configurable keybindings and old keybinding configuration compatibility
  are not included in this release.
- **Use `AGENTS.md`.** `CLAUDE.md` instruction discovery is not restored. Merge
  relevant instructions carefully rather than overwriting existing guidance.
- **Port plugins.** In-process TypeScript extensions are not supported. Existing
  subprocess plugins must also be checked against the v1 protocol.

The [version-matched migration guide](https://github.com/akonwi/kit/blob/v0.36.0/docs/releases/v0.36.0-migration.md)
is written for both users and coding assistants. Give it to your LLM with the
configuration and plugin source you want migrated, but never include credentials.
