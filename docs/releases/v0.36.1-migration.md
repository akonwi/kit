# Migrating to Kit 0.36.1

Use the source at tag **v0.36.1** when following these instructions.

## From 0.36.0

No configuration, credentials, or session-data migration is needed. Do not rewrite
credential stores or session databases. Upgrade the executable, verify `kit -v`,
and restart the server only when interruption of active sessions is acceptable.
Reopen clients after the server upgrade so message-history requests use matching
client/server implementations.

### Subagent model selectors

Agent definitions in `<Kit home>/agents/*.md` and project `.kit/agents/*.md` may
use bare model IDs. At delegation, Kit chooses the first matching available
provider in registration order. This differs from 0.36.0, where ambiguous bare
IDs could fall back to the parent model.

Use an explicit selector such as `openai-codex/gpt-5.6-sol` when provider identity
matters. Do not mechanically remove provider prefixes. An explicit selector
never selects another provider as an alternative match; if it is unavailable,
the existing warned fallback to the parent's active configuration still applies.
Reload after editing agent definitions. A successful parse does not prove provider
credentials or account access; verify delegation separately when needed.

### Composer history

Press Up in an empty composer to recall recent persisted user-message text.
Queued follow-ups take precedence. Selection inserts text for editing, not
execution; attachments and annotation selections are not restored. History is
bounded to the latest 500 messages. Direct-bash history remains a separate picker
and is not made fully durable by this release.

### Plugins

The plugin protocol and capability limits are unchanged. In particular,
`kit/session/submit-message`, `kit/system-prompt/set`, `kit/system/open-url`, and
plugin footer click callbacks remain unsupported. Changes to privately installed
plugins are not shipped by this Kit release.

## From 0.35.x or earlier

Follow the [0.36.0 migration guide](v0.36.0-migration.md) first, then the adjustments
above. Preserve user intent, back up configuration before edits (including the
contents of symlink targets), and test extensions with both an isolated `KIT_HOME`
and a trusted fixture project. Do not import or rewrite legacy runtime data.
