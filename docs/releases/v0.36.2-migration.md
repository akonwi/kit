# Migrating to Kit 0.36.2

Use the source at tag **v0.36.2** when following this guide.

## From 0.36.x

No settings, credentials, or session-data conversion is required. Upgrade the
executable, verify `kit -v`, and restart the server when interruption of active
work is acceptable. Reopen clients afterward.

### Review symlinked context sources

Kit now follows symlinks for discovered context files (including `AGENTS.md`),
skill search directories and nested skill directories, `SKILL.md` files, prompt
search directories, and Markdown prompt files. Targets may be outside the
configuration or project directory. Sources previously skipped can now load.
Only link to trusted instruction and prompt content; this is not a sandbox.

Users and coding assistants should:

1. Inspect existing symlinks and verify their targets are intentional and readable.
2. Keep the existing formats and locations; no copying or flattening of a
   symlink-managed configuration repository is necessary.
3. Before editing configuration through a symlink, back up the target contents
   and remember that the edit changes the shared source.
4. Reload discovery after source changes. Broken links and non-regular file
   targets do not load. Context and skill diagnostics help identify omissions.
5. Test changes with an isolated `KIT_HOME` and trusted fixture project. Isolation
   alone does not prevent linked sources from referencing files outside it.

Context aliases resolving to the same canonical path are deduplicated. Skill
traversal skips revisited resolved directories and retains depth, directory,
entry, and content limits. This fix does not introduce support for arbitrary
special files or change other extension protocols.

Do not rewrite credential stores, import legacy session databases, or infer
successful model/MCP connectivity from discovery alone.

## From 0.35.x or earlier

Follow the [0.36.0 migration guide](v0.36.0-migration.md) first, then the
[0.36.1 adjustments](v0.36.1-migration.md) and this guide. Native runtime data
remains separate from legacy history; legacy sessions are not imported.
