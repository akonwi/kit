Kit 0.37.0 makes client/server upgrades safer and improves the native terminal reading and workspace experience. It is the first stable release covered by Kit's protocol-40 cross-release compatibility contract.

## What's changed

- **Safer daemon attachment.** A client no longer replaces an incompatible running daemon on startup. Mismatches identify both versions and protocols; `kit server status` reports compatibility. If a daemon changes while the TUI is attached, Kit retains the visible transcript and unsent draft, stops using the incompatible attachment, and lets you explicitly recheck after resolving the mismatch. It does not replay an ambiguous prompt automatically.
- **Stable protocol-40 compatibility.** Canonical stable releases starting with 0.37.0 can share a daemon in either direction while both retain session protocol 40. Protocol skew and differing prerelease/development labels are not covered by that promise. This is a wire contract, not a promise that an older binary can reopen a database migrated by a newer one.
- **Durable direct-shell history.** `!` and `!!` commands have their own session history and can be recalled from the composer after reconnect or restart. Excluded `!!` commands remain out of model context; included `!` commands appear as context boundaries rather than synthetic bash-role transcript messages.
- **Explicit image inspection.** `show_image` presents the image in the transcript without automatically sending its bytes to the model. Use `inspect_image` when the model needs to examine image content. Saved image presentations remain available after reconnect.
- **Session deletion.** Deleting a saved session removes its owned records and artifacts rather than only hiding it. Deletion is irreversible, rejects active work, and reserves the deleted session ID against reuse. Independently owned or copied content in other sessions is not deleted.
- **Provider handling.** Supported public OpenAI GPT-6 standard Responses models can record reasoning-effort changes at user-message boundaries without rewriting prior requests. Kit also treats OpenAI's `misalignment_policy_violation` as a non-retryable stop; partial tool calls from that failed response are not executed. These behaviors do not imply support for Codex, custom gateways, or other providers.
- **Terminal refinements.** File headers stay visible while scrolling the continuous Diff document; live working-tree diffs follow authoritative workspace changes. Newly delivered long responses begin at the top of the Agent transcript, with live section navigation. History pickers, narrow footer layout, and recovered-run feedback are improved.

## Upgrade and get started

```sh
brew update && brew upgrade akonwi/tap/kit
kit version
kit server status
kit
```

Homebrew availability follows the formula update. For manual installation, download the archive for your OS and architecture, extract its single `kit` executable, install it on PATH, and verify `command -v kit` and `kit version`. The archives are `kit_v0.37.0_darwin_arm64.tar.gz`, `kit_v0.37.0_darwin_amd64.tar.gz`, `kit_v0.37.0_linux_arm64.tar.gz`, and `kit_v0.37.0_linux_amd64.tar.gz`.

**A running 0.36.x daemon requires an explicit restart when upgrading.** Version 0.36.2 uses protocol 39, while 0.37.0 uses protocol 40. The new client will report the mismatch without stopping the old daemon. Let active work settle, then run `kit server restart` with the new binary when interruption is acceptable; reopen older clients with the new binary afterward. See the [0.37.0 migration guide](https://github.com/akonwi/kit/blob/v0.37.0/docs/releases/v0.37.0-migration.md) for the version-matched steps and image/shell behavior changes. Upgrades from 0.35.x or earlier also require the [0.36.0 migration guide](https://github.com/akonwi/kit/blob/v0.36.0/docs/releases/v0.36.0-migration.md); legacy runtime data is not imported.

## Platforms and verification

The release workflow builds and smoke-tests four Go-executable archives. macOS targets 14.0 or newer; Linux builds use Ubuntu 24.04 with a glibc 2.39 baseline, not a fully static binary. Windows and npm distribution are unsupported. Plugins and MCP servers may require separate runtimes. The native macOS application is not bundled in these Go archives.

Local build, vet, full Go tests, race tests, workflow lint, and an extracted Apple Silicon binary's version/help smoke passed before tagging. These checks do not establish authenticated provider/MCP coverage, installed cross-platform upgrade behavior, or pinned C/SDK toolchains. The release workflow must still pass on all four targets before publication; Homebrew installation and manual extraction need verification after assets are available.
