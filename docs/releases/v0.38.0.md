# Kit 0.38.0

This release adds explicit, durable communication between subagents and updates the session protocol to 41. The native macOS app is released separately as 0.1.1.

## What's changed

- A parent agent can ask a configured child for a reply or send a request without waiting. Children can send requests to configured siblings, inspect receipts and their inbox, and explicitly reply; children do not gain sibling lifecycle controls. Requests, replies, and parent notifications survive server restarts, with bounded delivery and terminal failure handling.
- Parent-directed subagent mailbox entries now identify whether they report a task completion or a request reply. This **changes the snapshot wire contract** and requires session protocol 41; it is not compatible with the 0.37.x protocol-40 daemon or clients.

## Upgrade and get started

```sh
brew update && brew upgrade akonwi/tap/kit
kit version
kit server status
```

Homebrew availability follows the formula update. For manual installation, download `kit_v0.38.0_<platform>.tar.gz` for your OS and architecture, extract its single `kit` executable onto PATH, then verify `command -v kit` and `kit version`. Platforms: `darwin_arm64`, `darwin_amd64`, `linux_arm64`, `linux_amd64`.

**A running protocol-40 daemon must be restarted explicitly.** The new client reports the mismatch and leaves it running. Let active work settle, then run `kit server restart` with the new binary when interruption is acceptable; update all attached CLI clients and the separately installed macOS app. The 0.1.0 app cannot attach to a protocol-41 server; app 0.1.1 is the corresponding update. Do not point a 0.37.x daemon at native data migrated by 0.38.0. Follow the [0.38.0 migration guide](https://github.com/akonwi/kit/blob/v0.38.0/docs/releases/v0.38.0-migration.md) before changing binaries.

## Compatibility and limitations

Canonical stable releases starting at 0.38.0 can share protocol-41 daemons if they retain protocol 41. Development and differing prerelease labels, protocol-40 clients, and database downgrades are not covered by that promise. See the migration guide for restart, backup, and integration checks. Open backlog items remain outstanding, including multimodal token accounting and parts of migration/authentication, settings, and protocol verification.

macOS CLI archives target macOS 14+; Linux builds use Ubuntu 24.04 (glibc 2.39 baseline). Linux archives are not fully static. Windows and npm distribution are unsupported. The CLI archives do not contain the macOS app. Plugins and MCP integrations may need separate runtimes.

On the preparation checkout, tracked Go formatting, build, vet, full Go and race tests, workflow lint, generated macOS wire check, full macOS tests, and an extracted Apple Silicon CLI's version/help smoke passed. The app's arm64 ad-hoc Release staging build passed metadata and fixture checks but is **not distributable**. The CLI dry run and app staging build were stamped with the then-current preparation commit, not the final release commit; repeat them on the reviewed final commit. All four hosted CLI build/smoke results, signing/notarization, Homebrew installation, and final manual extraction still require verification. These local checks do not establish authenticated provider/MCP coverage or cross-platform installed-upgrade behavior.
