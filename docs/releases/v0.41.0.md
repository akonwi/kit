# Kit 0.41.0

This release lets you fork a session while it is working and send the child's first message as part of the fork. It also removes size limits that could reject or truncate transcript history, and it advances the session API to protocol 44. The native macOS app is released separately and is not included in CLI archives.

## What's changed

- Forking no longer waits for a session to go idle. A fork copies the source's latest settled boundary, so an active turn, queued follow-ups, a bash execution, or a compaction keeps running in the source and is not copied into the child.
- A fork can carry the child's first message. In the TUI, `/fork <message>` opens the child and starts that turn there. If the turn cannot start, the fork still succeeds and the child shows the error like a failed prompt submission, with your message restored to the composer.
- Transcript history is complete. Snapshots, message pages, transcript pages, and subagent transcripts are bounded by pagination only, so tool-call arguments over 64 KiB are no longer dropped from history and large messages no longer cause transcript or subagent page errors. The CLI and Go client SDK no longer cap the total size of ordinary responses.
- MCP tool results are no longer rejected for exceeding a byte limit.
- Error responses keep their error codes regardless of message length. The server writes renderer-safe messages of at most 1,024 bytes, and clients reject only blank or unsafe messages.
- Server-sent event streams end cleanly when the daemon shuts down.
- TUI workspace tabs are spaced apart for easier scanning.

## Upgrade and get started

```sh
brew update && brew upgrade akonwi/tap/kit
kit version
kit server status
```

For manual installation, download `kit_v0.41.0_<platform>.tar.gz`, extract its single `kit` executable onto PATH, and verify `kit version`. Supported archives are `darwin_arm64`, `darwin_amd64`, `linux_arm64`, and `linux_amd64`.

Protocol 44 is not compatible with protocol-43 clients or daemons. Let active work settle before explicitly restarting the daemon with the new binary (`kit server restart`), then update attached CLI clients. The CLI leaves an incompatible running daemon untouched. Back up state before operational changes and do not attempt a database downgrade.

## Go client SDK changes

Code using the `kit` package (`github.com/akonwi/kit/api`) must be updated for protocol 44:

- `Client.ForkSession` returns `kit.ForkSessionResult` instead of `kit.SessionInfo`. Read the child from `result.Session`. When the input carried a prompt, `result.FirstTurnError` is set if the first turn could not start; the fork itself still succeeded. Its `Code` is one of `invalid_request`, `not_found`, `conflict`, `unavailable`, or `internal`.
- `ForkSessionInput.ID` is removed; the server chooses the child's ID. Set the optional `ForkSessionInput.Prompt` to start the child's first turn as part of the fork. Fork prompts can carry text and attachments but not annotations.

```go
result, err := client.ForkSession(ctx, sourceID, kit.ForkSessionInput{
	Prompt: &kit.PromptInput{Text: "explore the other approach"},
})
if err != nil {
	return err
}
child := result.Session
if result.FirstTurnError != nil {
	// The child exists; report the failure like a failed prompt submission.
}
```

## Compatibility and limitations

Canonical stable 0.41.0-or-later releases that retain protocol 44 may share a protocol-44 daemon. Development builds and prerelease labels are outside that compatibility promise. The published macOS app (0.1.2) uses an earlier protocol and is not compatible with this daemon; an updated app is released separately. macOS CLI archives require macOS 14+; Linux archives use Ubuntu 24.04 (glibc 2.39 baseline) and are not fully static. Windows and npm distribution are unsupported.

Live session events remain bounded per event: tool arguments, output, and details that exceed those bounds are marked truncated or omitted in the live view and are complete in the transcript once the turn is stored. The CLI archives do not contain the separately distributed macOS app. Plugins and MCP integrations may require their own runtimes.
