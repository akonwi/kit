# Kit 0.44.0

Clients and servers that speak the same session protocol are now compatible no matter what their release labels say. The command palette asks for a path when you run `/cd` without one. This release also fixes a droids resume bug that could leave a turn unable to settle. The native macOS app is released separately and is not included in CLI archives.

## What's changed

- `a2542253` — feat(core): decide client/server compatibility by protocol alone
  - A client can attach to a server when both speak the same session protocol. Release labels, including development builds and release candidates, are still reported for diagnosis but no longer block attachment. This replaces the list of stable releases allowed for each protocol.
  - `kit server status` reports `compatible` for any server on the client's protocol.
- `c06f9308` — feat(tui): prompt for a missing `/cd` path in the palette
  - Running `/cd` without a path turns the command palette into a path input in the same frame. Enter runs the command, an empty submission shows an inline error, and Escape returns to the command list with its query and selection intact. Only built-in commands prompt; extension commands don't declare whether their argument is required.
- `788cb5ec` — fix(droids): resume calls that completed before a later hook parked (#169)
  - Suppose a `BeforeToolCall` hook parked a later call in the same step. On resume, the result of an earlier call that had already completed could be dropped. The provider then received a call with no output, and the turn could not settle. Resume now processes every admitted call in the step. Completed calls reuse their stored result, so no tool runs twice.
- `fe39b1fe` — fix(tui): let interaction option labels use the row's width
  - Option labels are no longer capped at 32 cells. In narrow rows, details shrink before labels, and the selection bar stays visible.
- `48b07076` — fix(tui): submit composer through text area action
- `d159feec` — refactor(core): give daemon publication one owner and move lifecycle out of server (#167)
  - Daemon discovery files now have a single owner, and client-side daemon lifecycle code is in its own package. On-disk format, paths, and the wire protocol are unchanged. A malformed daemon registry now reports `validate daemon registry: …`, and publication rejects URLs that contain user info.

## Compatibility and limitations

The session protocol is still 45, and Kit's stored data format is unchanged. A running 0.42.x or 0.43.x daemon keeps serving 0.44.0 clients, and older stable clients from 0.42.0 on can attach to a 0.44.0 daemon. From 0.44.0 on, any build on protocol 45 is accepted, including development builds and release candidates. Older clients still apply their stable-release check to the server's label.

macOS CLI archives require macOS 14 or newer. Linux archives use Ubuntu 24.04 with a glibc 2.39 baseline and are not fully static. Windows and npm distribution are unsupported.
