# Kit 0.46.0

Kit servers can now be used from other machines. A server pairs devices, can be served on a tailnet with `kit server expose --tailscale` or behind your own tunnel or proxy, and `kit attach` connects to it by URL. Provider logins, server settings, and MCP server authorization now run through the server's API, so they work the same whether the server is on this machine or another. The terminal client also reports its state through the Program Status Protocol. This release moves the session protocol from 46 to 47, so it doesn't work with a running 0.45.x daemon or with the published macOS app; see the upgrade guide. The native macOS app is released separately and is not included in CLI archives.

## What's changed

- `a0b6559b` — Remote access phase 1: pairing, URL servers, Tailscale expose, deployment docs (#190)
  - `kit server pair [--url URL]` prints a single-use pairing link (`https://host/pair#CODE`) that expires after 5 minutes. A device that redeems it gets a device token. The server stores only its hash, and it expires after 30 idle days or a year after pairing, whichever comes first. `kit server devices [list|revoke ID]` lists and revokes devices; revoking ends that device's open requests. See `docs/features/pairing.md`.
  - `kit servers add NAME LINK` pairs and saves a server by URL, and `kit attach NAME|URL|LINK` and `kit pair [SERVER]` attach and pair. Device tokens are kept in an owner-only `$KIT_HOME/server-tokens.json`, each bound to the URL that issued it. The TUI command palette has a **pair** command that shows copyable links.
  - `kit server expose --tailscale [--off] [--https-port N]` serves this machine's server on its tailnet with Tailscale Serve. It never uses Funnel. `--off` undoes only what it added.
  - `kit server run` runs the server in the foreground for service managers and containers. Kit never restarts a foreground server.
  - New sessions on a server on another machine start in the server user's home directory, or in `--cwd`, which names a path on that machine. Paths in the footer, session picker, and `#` mentions are shown relative to the server's home.
  - Failed authentication and pairing attempts are rate-limited per address. A request without valid credentials must send its body within 10 seconds.
  - `docs/features/remote-deployment.md` covers private networks, Cloudflare Tunnel, reverse proxies, public exposure, and cloud hosts.
- `245e2765` — feat: log in to providers through the server API (#194)
  - `/login` and `kit auth login|logout` log in to the attached server and store credentials in the server's home. They work on a server on another machine too. For Claude's browser login, the client receives the browser's redirect on `localhost:53692` and relays it to the server. When it can't listen there, you paste the redirect instead.
  - `kit auth status` reports on a running server and never starts one.
- `4469934c` — feat: serve server settings through the session API (#196)
  - `GET` and `PATCH /v1/settings` read and change the server's `defaultModel`, `compactionModel`, `modelOverrides` (context windows), `promptCacheRetention`, and `readClaudeConfigs`. See `docs/features/server-settings.md`.
  - **`kit` and `kit -p` without `--model` now start new sessions with the server's `defaultModel`.** Without one, the server picks a model you have credentials for. A new session starts at its model's default thinking level.
  - The context-window editor in `/model` (Ctrl+O) saves to the attached server.
  - The server now writes `settings.json` atomically and keeps symlinks and file mode. If the file can't be parsed, the settings API returns an error and new sessions use built-in defaults.
- `31317704` — feat(core): authorize MCP servers through attached clients (#197)
  - When an MCP server needs OAuth, the session asks you in place of the composer, with the page to open. The server no longer opens a browser or listens for the redirect. In the terminal client, Return opens the page. The client receives the browser's redirect on `127.0.0.1:53173` on its own machine and Kit continues. If it can't listen there, you paste the address the browser ended up at. See `docs/features/mcp-authorization.md`.
  - The request waits up to five minutes, including while no client is attached, and then fails the tool call. Subagents and `kit -p` can't ask; they fail with an explanation and keep any saved credential.
- `0f4517c1` — feat(tui): report status through the Program Status Protocol (#195)
  - The terminal client reports whether it is working, waiting for you (sign-in, a permission, or a question), done, or failed through OSC 7501. Terminals that support the protocol notify from it, and Kit then only rings the bell. Inside tmux, Screen, and Zellij no reports are sent.
- `5ce4d461` — feat(core): bind builds to isolated Kit homes with channels (#198)
  - For development builds: a build made with `--define channel=NAME` defaults to `~/.local/state/kit/NAME/home` instead of `~/.kit`. Release builds name no channel and still use `~/.kit` or `KIT_HOME`.
- `0eee5170` — docs(tui): describe tool output wells
- `d4a10429`, `aa4268fd`, `883dcc3d` — macOS app changes (Paper redesign with a tiled workspace, composer caret, session tab tree). They ship with the next macOS app release, not in this CLI.

## Upgrade guide

Kit 0.46.0 moves the session API from protocol 46 to protocol 47. Protocol-46 clients and daemons, including Kit 0.45.x, and the published macOS app 0.1.3 (protocol 45) can't connect to a 0.46.0 daemon. A 0.46.0 client refuses a running protocol-46 daemon and won't replace it on its own. Let active work settle, upgrade Kit, and then restart the daemon:

```sh
brew update && brew upgrade akonwi/tap/kit
kit server restart
kit version
kit server status
```

The daemon adds a `devices` table to `kit.db` (migration 16) on first start. Back up `$KIT_HOME` before upgrading if you may need to go back; older releases can't reopen a migrated database.

After upgrading:

- **Default model.** `kit` without `--model` now uses `defaultModel` from the server's `settings.json`. If you relied on the client choosing a model, set `defaultModel`, or keep passing `--model`.
- **Login.** `kit auth login` now logs in to this home's server and starts it like `kit` does. Saved credentials are unchanged.
- **MCP OAuth.** Saved MCP credentials keep working. A new authorization is answered in the client: open the page and approve, and the terminal client continues on its own. The macOS app 0.1.3 can't connect to this daemon at all.
- **Remote access** is opt-in. Nothing listens beyond loopback until you set `server.listen`, run `kit server expose --tailscale`, or run the server behind your own proxy. Read `docs/features/remote-deployment.md` first: Kit doesn't terminate TLS.

Update every attached CLI or Go client to a protocol-47 version. The public Go client (`github.com/akonwi/kit/api`) changes as follows:

- `CreateSessionInput.Model` is optional. Leave it empty to use the server's default.
- New: `Pair(ctx, link, deviceName)` redeems a pairing link, and `Client.CreatePairing`, `Devices`, and `RevokeDevice` manage devices.
- New: `Client.Providers`, `StartProviderLogin`, `WaitProviderLogin`, `SubmitProviderLoginAuthorization`, `CancelProviderLogin`, `SetProviderAPIKey`, and `Logout` run provider logins on the server.
- New: `Client.ServerSettings`, `UpdateServerSettings`, and `SetModelContextWindow` read and change server settings.
- New: the `authorize` interaction kind, with `URL` and `RedirectURI`. A client that can't present it should still let the user cancel it.
- New error codes: `credential_expired` (401) for an expired device token, which needs pairing again, and `rate_limited` (429) for too many failed authentications or pairing attempts.

For manual installation, download `kit_v0.46.0_<platform>.tar.gz`, extract its single `kit` executable onto PATH, and verify `kit version`. Don't try to downgrade the database.

## Compatibility and limitations

Any build on protocol 47 can attach to a 0.46.0 daemon. The published macOS app (0.1.3) uses protocol 45 and can't connect until an updated app is released. The macOS app also can't reach servers on other machines yet (#145, #186).

Kit doesn't terminate TLS. Serve it through Tailscale Serve, a tunnel, or a reverse proxy that does; plain `http://` pairing links send the code and device token unencrypted. SSH connections (#185) and server-hosted terminals (#184) aren't available yet.

An MCP authorization request doesn't survive a server restart (#133). In the macOS app, a pasted address is the only way to finish one. Two terminal clients waiting for MCP authorization on the same machine share `127.0.0.1:53173`; the second one asks you to paste.

macOS CLI archives require macOS 14 or newer. Linux archives use Ubuntu 24.04 with a glibc 2.39 baseline and are not fully static. Windows and npm distribution are unsupported.
