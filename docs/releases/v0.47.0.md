# Kit 0.47.0

Context that Kit adds to a conversation, such as a working-directory change, a fork, or a subagent's request or reply, is now part of the transcript as soon as it is created, not only after the turn that uses it. This release also adds OpenCode Zen as a provider, shows each session's activity in the session picker, and fixes live subagent transcripts that failed to load. It moves the session protocol from 47 to 48, so it doesn't work with a running 0.46.x daemon or with the macOS app 0.2.0; see the upgrade guide. The native macOS app is released separately and is not included in CLI archives.

## What's changed

- `a0924bca` — feat: show context markers and boundaries from creation (#207)
  - The server records a context boundary in the transcript when it is created. A snapshot lists boundaries that haven't joined a completed turn yet as context records without a turn, after the turn messages. `pendingBoundaries` is gone.
  - The session and subagent live streams add a `boundary.created` event.
  - In the terminal client, a finished composer command (`!`) shows up as soon as it ends, including a command run from another client, and a row stays in place when its run joins the turn history.
  - Subagent request and reply records (`subagent_inbox`) carry `from`, `message`, and `failure` details.
- `d6fa2585` — fix(subagents): keep child live events within the wire contract
  - Live subagent transcripts loaded with HTTP 500 once the subagent planned a tool call, because the event named an assistant message, which the subagent event contract forbids. Clients kept retrying and never showed the live transcript. Tool events no longer name a message, and empty text or thinking deltas are skipped.
- `20fa437b` — feat(providers): add OpenCode Zen support (#204)
  - OpenCode Zen is the `opencode` provider, with its models.dev catalog of `opencode/*` models through `https://opencode.ai/zen/v1`. As with OpenCode Go, each model goes through Responses, Chat Completions, or Anthropic Messages according to its metadata.
  - Zen keeps its own stored API key, set with `/login` or `kit auth login opencode`. `OPENCODE_API_KEY` enables both Zen and OpenCode Go.
  - A new session without a model or a configured default now falls back to `opencode-go/kimi-k2.7-code`, then `opencode/gpt-5.6-sol`, when no Codex, OpenAI, or Anthropic credentials are available. Existing OpenCode Go preferences are kept.
  - Provider stream failures are logged in full before Kit shows a sanitized error, and Chat Completions HTTP failures are classified correctly.
- `afd84bfd` — feat: show session activity in the session picker (#203)
  - The terminal session picker and `kit sessions` mark sessions that are working with a spinner and sessions waiting on you (a permission, question, or plugin dialog) with a `?`. A parent session counts as working while its subagents run. Idle sessions stay unmarked.
  - New `GET /v1/sessions/activity` lists sessions that aren't idle, without loading their runtimes.
- `bd1617ef`, `e6558e7b`, and the macOS part of `a0924bca` — macOS app changes (terminal tabs, focus follows the pointer by default, transcript markers). They ship in the macOS app 0.3.0, not in this CLI. `bd9493d3`, `c045b5ce`, `f37dd6db`, `7f24e832`, and `5e57cdb0` shipped in the macOS app 0.2.0.

## Upgrade guide

Kit 0.47.0 moves the session API from protocol 47 to protocol 48. Protocol-47 clients and daemons, including Kit 0.46.x and the macOS app 0.2.0, can't connect to a 0.47.0 daemon. A 0.47.0 client refuses a running protocol-47 daemon and won't replace it on its own. Let active work settle, upgrade Kit, and then restart the daemon:

```sh
brew update && brew upgrade akonwi/tap/kit
kit server restart
kit version
kit server status
```

This release adds no database migration.

If you use the macOS app, upgrade it to 0.3.0, which speaks protocol 48. App 0.2.0 refuses a 0.47.0 daemon with a message saying which side to update.

Update every attached CLI or Go client to a protocol-48 version. The public Go client (`github.com/akonwi/kit/api`) changes as follows:

- **Removed:** `SessionSnapshot.PendingBoundaries` and the `PendingBoundary` type. Boundaries that haven't joined a completed turn are now entries in `SessionSnapshot.Messages` with role `context`, a `BoundaryID`, an empty `TurnID`, and no `Sequence`. They follow all turn messages. Code that assumed every snapshot message has a turn must handle these records.
- **New:** the `boundary.created` session event (`BoundaryCreatedEvent`) and subagent event (`SubagentBoundaryCreatedEvent`). They announce a context record when it is created. Reconcile it with the snapshot record by `BoundaryID`.
- **New:** `Client.SessionActivity` returns `SessionActivityEntry` values with status `running` or `awaitingResponse`. A session missing from the result is idle.

## Compatibility and limitations

The session protocol is 48. Kit's stored data format is unchanged.

Subagent live streams still drop single events over 16 KiB, such as a large tool result, until the subagent's transcript reloads ([#209](https://github.com/akonwi/kit/issues/209)). One invalid event still fails every page of a subagent's live stream that holds it ([#208](https://github.com/akonwi/kit/issues/208)).

macOS CLI archives require macOS 14 or newer. Linux archives use Ubuntu 24.04 with a glibc 2.39 baseline and are not fully static. Windows and npm distribution are unsupported.
