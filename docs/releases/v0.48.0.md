# Kit 0.48.0

Kit can now attach to a Kit server on another machine over SSH, with no served URL, pairing, or stored secret. The terminal client also gains a context menu for selected text. The session protocol stays at 48, so this release works with a running 0.47.0 daemon and with the macOS app 0.3.0 and later. The native macOS app is released separately and is not included in CLI archives.

## What's changed

- `d5159342` — feat(core): connect to Kit servers over SSH (#211)
  - `kit attach me@devbox` and `kit attach ssh://me@devbox:2222` attach to the server of the host's default Kit home over your system `ssh`, so your SSH configuration, agent, and jump hosts apply. A bare host or `~/.ssh/config` alias works once saved with `kit servers add devbox devbox`; an unsaved bare name is reported as an unknown server rather than tried over SSH.
  - The first attach starts the host's server if it isn't running. Kit checks that the host speaks the same session protocol, says which side to upgrade if not, and forwards a free loopback port to the server. When the connection drops or the host's server restarts, Kit reconnects without prompting, which needs an SSH agent, a key without a passphrase, or connection sharing. Reconnecting never starts a stopped server.
  - `kit servers` checks saved SSH servers without starting them or prompting. Pairing another device through an SSH server needs `kit pair NAME --url URL`.
  - `kit server status --json` prints a read-only report of the server's home, process, address, versions, instance, database readiness, and local token. Plain `kit server status` is unchanged and never prints the token.
  - See [Servers over SSH](https://github.com/akonwi/kit/blob/main/docs/features/attach.md#servers-over-ssh).
- `f5bffd8b` — feat(tui): add a context menu for selected text
  - A secondary click on selected text opens a menu with **Copy** and **Quote**. Copy works like Cmd+C, selection pulse included. Quote appends the selection to the composer as a Markdown block quote and focuses the composer.
- `a97e1d72` — the Ard Mermaid renderer now regenerates shared fixtures (`testdata/mermaid`) that the macOS app's port tests against. Drawing in the terminal client is unchanged.
- `0aa6f2b0`, `b4a2f91c`, the macOS part of `a97e1d72`, `9e18a1f8`, and `dc94f234` — macOS app changes. They ship in the macOS app 0.4.0, not in this CLI.

## Compatibility and limitations

The session protocol is 48, unchanged from 0.47.0, and Kit's stored data format is unchanged. Clients and daemons from 0.47.0 and 0.48.0 work together, so you can upgrade without restarting the daemon. Restart it (`kit server restart`) when convenient to pick up the new `kit server status --json` report.

Attaching over SSH needs Kit 0.48.0 or newer on the host, on the `PATH` of commands run over SSH. An older Kit there is reported as too old to attach over SSH. The macOS app attaches to the local server only and can't use SSH servers yet ([#186](https://github.com/akonwi/kit/issues/186)).

The terminal client can still panic while opening a session, in the background syntax highlighter ([#210](https://github.com/akonwi/kit/issues/210)).

Subagent live streams still drop single events over 16 KiB, such as a large tool result, until the subagent's transcript reloads ([#209](https://github.com/akonwi/kit/issues/209)). One invalid event still fails every page of a subagent's live stream that holds it ([#208](https://github.com/akonwi/kit/issues/208)).

macOS CLI archives require macOS 14 or newer. Linux archives use Ubuntu 24.04 with a glibc 2.39 baseline and are not fully static. Windows and npm distribution are unsupported.
