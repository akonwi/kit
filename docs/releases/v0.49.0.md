# Kit 0.49.0

Kit now tells you when a newer release is out, and `kit update` installs it. The terminal client also gains a `/settings` dialog, and `/login` is now `/connect`, where you can also log out of a provider. The session protocol stays at 48, but creating a pairing code from Kit 0.48.0 or older fails against a 0.49.0 server, so upgrade Kit on the machine where you pair devices (see the upgrade guide). The native macOS app is released separately and is not included in CLI archives.

## What's changed

- `8150e1f6` — feat: check for updates and release notes in the TUI, CLI, and macOS app (#220)
  - `kit update` shows the newest `vX.Y.Z` release's summary and link, then asks before installing it. If Kit was installed with Homebrew, it runs `brew upgrade akonwi/tap/kit`. Otherwise it downloads `kit_vX.Y.Z_<os>_<arch>.tar.gz`, checks it against the SHA-256 digest GitHub publishes, checks that the new executable reports the new version, and replaces the old one in place. The executable's directory must be writable.
  - The local server keeps running the old Kit until it restarts. When the server runs an older version, `kit update` says how many sessions are working or waiting on you, which a restart interrupts, and asks whether to restart it. It does this even when the CLI is already up to date. Servers on other machines are never changed; update Kit on that machine.
  - `kit update --yes` installs without asking, for scripts. It restarts the local server only when the server reports that no session is working or waiting on you. Without `--yes`, `kit update` needs a terminal to ask in and exits with status 2 otherwise.
  - The terminal client checks GitHub's releases at startup and every six hours. A failed check is silent. When a newer release exists, the left of the footer reads `Update available: vX.Y.Z`, unless a session's queue or reconnection status is using that place. Click it to see the release's summary. **Update** installs it in the background and shows progress in the footer. A failed install shows its reason in the footer, and clicking it offers to try again.
  - Once the update is installed, the footer reads `Restart to finish update` when you're attached to this home's server and it runs an older release. Otherwise it reads `Relaunch to finish update`. The dialog says how many sessions a restart interrupts. **Restart** restarts this home's server and reopens the client on the same session. **Relaunch** reopens only the client, and the server keeps its version. A temporary session is disposed when the client exits, so relaunching opens a new temporary session in the same directory.
  - `/release-notes` opens the running version's release on GitHub.
  - Development builds and builds bound to a channel never check, and `kit update` refuses to replace them.
  - See [Updates and release notes](https://github.com/akonwi/kit/blob/main/docs/features/releases.md) and [ADR 0048](https://github.com/akonwi/kit/blob/main/docs/adrs/0048-check-for-updates-from-each-client.md).
- `6f317448` — feat: add settings surfaces to the TUI and macOS app (#216)
  - `/settings` opens a dialog with two sections. **Server** reads and changes the attached server's default model, compaction model, prompt cache retention, and Claude Code commands through the existing settings API (`GET`/`PATCH /v1/settings`). **This terminal** holds the diff layout, diff line wrapping, and theme, saved in this Kit home's `settings.json`.
  - Each change saves at once. A row shows a spinner while it saves. If saving fails, the row keeps the last confirmed value and shows the reason beneath it. When the server's settings can't be read, the Server section says why and `Ctrl+R` reloads them.
  - The Diff tab's Split/Unified choice is now saved as the `diffLayout` preference (`unified` or `split`).
  - See [Server settings](https://github.com/akonwi/kit/blob/main/docs/features/server-settings.md).
- `9db54b18` — feat(tui): log out of providers from /connect (#219)
  - `/login` is now `/connect`. Searching for "login", "logout", or "auth" still finds it.
  - In its provider list, `Ctrl+D` logs the selected provider out of the attached server. The Claude and Anthropic rows share one credential. A notification reports the result, including the server's reason when it refuses, such as for credentials that come from its environment.
  - The provider-login docs now also say that saving an API key for a provider that already has one replaces it. That behavior hasn't changed.
- `cbce15d4` — feat(macos): pair with and manage Kit servers on other machines (#221)
  - This release includes the change's server and Go client parts. `POST /v1/pairing` now also returns `urls`, the addresses the server is served at, with the loopback URL last. The Go client exposes them as `api.Pairing.URLs`, and `contract.PairingCode` gains `URLs` and `contract.MaxPairingURLs`. `kit pair` doesn't use them yet ([#222](https://github.com/akonwi/kit/issues/222)). Older clients can't read this new field; see the upgrade guide.
- `aaad1531` — test(core): synchronize git descendant-kill test on child startup (#218). This change is test-only.
- `7d9c85cd`, `1ef102bc`, `9d22897b`, `c67798b9`, `1458f807`, `86d653ba`, and `1207108c`, plus the macOS parts of `6f317448`, `8150e1f6`, and `cbce15d4`, are macOS app changes. They ship in the macOS app's own release, not in this CLI.

## Upgrade guide

- **Creating a pairing code from Kit 0.48.0 or older fails against a 0.49.0 server.** `POST /v1/pairing` now returns a `urls` field. Older Kit rejects response fields it doesn't know, and this request skips the session protocol check, so you get a decode error instead of a version message, roughly `create pairing code: Kit server protocol violation: decode daemon session response: json: unknown field "urls"`. This affects every way an older Kit creates a pairing code, whether for this home's server or a saved server on another machine:
  - `kit pair`
  - `kit server pair`
  - the pairing link at the end of `kit server expose --tailscale`
  - the terminal client's `/pair` dialog
- **What to do:** upgrade Kit to 0.49.0 on the machine where you create the pairing code. Kit 0.49.0 can still create pairing codes on 0.47.0 and 0.48.0 servers, because those servers don't send `urls`. Redeeming a pairing link and other requests are unaffected.
- **Go programs** using `github.com/akonwi/kit/api` from 0.48.0 or older fail the same way when they call `CreatePairing` against a 0.49.0 server. Update the module to v0.49.0.
- **Upgrading the CLI:** you can't use `kit update` to reach 0.49.0, because 0.48.0 doesn't have it. Run `brew upgrade akonwi/tap/kit`, or download the release archive for your platform. Then run `kit update`. It reports 0.49.0 as up to date, then offers to restart a local server that still runs the old version, saying how many sessions the restart interrupts. You can also run `kit server restart` when convenient.
- Nothing else changes: the session protocol and Kit's stored data format are the same as in 0.48.0.

## Compatibility and limitations

The session protocol is 48, unchanged since 0.47.0. Apart from creating pairing codes (see the upgrade guide), clients and servers from 0.47.0, 0.48.0, and 0.49.0 work together, and the macOS app 0.3.0 and later can use a 0.49.0 server. The `/settings` dialog's Server section works with servers from 0.47.0 on.

This is the first release with `kit update` and the terminal client's update checks, so updating from 0.49.0 can be done end to end only once a later release is published. That path hasn't been tested from a published 0.49.0 yet. If one `kit update` has been downloading for over an hour, another `kit update` run in the same directory can remove its staged download ([#226](https://github.com/akonwi/kit/issues/226)). The update check calls GitHub's API without authentication, and no setting turns it off.

The terminal client can still panic while opening a session, in the background syntax highlighter ([#210](https://github.com/akonwi/kit/issues/210)). Subagent live streams still drop single events over 16 KiB until the subagent's transcript reloads ([#209](https://github.com/akonwi/kit/issues/209)), and one invalid event still fails every page of a subagent's live stream that holds it ([#208](https://github.com/akonwi/kit/issues/208)).

macOS CLI archives require macOS 14 or newer. Linux archives are built on Ubuntu 24.04 with a glibc 2.39 baseline and are not fully static. Windows and npm distribution are unsupported.
