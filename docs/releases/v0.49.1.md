# Kit 0.49.1

This patch release fixes reliability problems: server shutdown and subagent cancellation could wait on a slow subagent, a slow or failing `git` was reported as "not a repository", and plugin RPC, event-stream idle detection, and server teardown had races. It adds no features and keeps session protocol 48. It's the first release that Kit 0.49.0's `kit update` can install. The native macOS app is released separately and is not included in CLI archives.

## What's changed

- `f3fb5ca0` — fix(core): keep subagent worker lock off child-runtime I/O (#259)
  - Stopping the server no longer waits past its deadline for a subagent whose runtime is slow to close.
  - Cancelling or dismissing a subagent no longer waits behind a steering message, transcript read, or thinking change that's still in progress.
  - Cancelling or dismissing a subagent just as it starts can no longer be undone by the start.
  - Changing a subagent's model right after it finishes no longer fails with a state conflict.
- `30cd5b77` — fix(core): keep last Git snapshot on transient probe failure (#262)
  - When `git` is slow (over the 2-second probe limit), fails to start, is killed, or fails inside a repository, the server keeps the last Git status it saw and tries again on the next poll. Before, clients and plugins were told the folder wasn't a repository (`git.changed` with `git: null`) until the next successful check.
  - A folder is reported as not a repository only when `git rev-parse` runs and says so, or when Git's output or the repository's local config can't be used.
  - If the first check for a folder fails, Git status starts as unknown and the next poll retries.
- `93fbc0ea` — fix(core): harden plugin RPC lock order, stream idle clock, and teardown (#263)
  - A plugin's response is now validated without holding the plugin connection's lock, which removes a lock-order inversion with plugin initialization.
  - The terminal client's Git status and plugin notification streams detect a stalled connection with the monotonic clock, so a system clock change can no longer drop a healthy stream early or delay detection. The monotonic clock pauses during sleep, so a stream that died while the computer slept reconnects up to 45 seconds after waking instead of right away.
  - When the server stops, it cancels requests that are still running, then waits up to 2 more seconds for them before closing its database and releasing its lock.
- `e89aa7ce` and `d3bd2a67` update contributor skills, and `954f2b05` and `5c48f649` change macOS CI. `946c4702`, `26562035`, `bc3c625c`, `400c18ef`, `b45be330`, `bf0348dc`, and `f33213b1` are macOS app, app docs, and app test changes. App changes ship in the macOS app's own release, not in this CLI.

## Compatibility and limitations

The session protocol is 48, and nothing on the wire changed since 0.49.0. Clients and servers from 0.47.0 through 0.49.1 work together, with the pairing-code exception described in the [0.49.0 upgrade guide](https://github.com/akonwi/kit/blob/main/docs/releases/v0.49.0.md#upgrade-guide). Kit for macOS 0.3.0 and later can use a 0.49.1 server.

To upgrade from 0.49.0, run `kit update`. If Kit was installed with Homebrew, it runs `brew upgrade akonwi/tap/kit`. From 0.48.0 or older, run `brew upgrade akonwi/tap/kit` or download the release archive for your platform. A running server keeps the old version until it restarts; `kit update` offers to restart this home's server, or run `kit server restart` when convenient.

Known issues: if Git keeps failing in a folder, such as one that was deleted, the last Git status stays until a check succeeds. Dismissing a subagent just as it finishes can leave its stored conversation until the server restarts ([#258](https://github.com/akonwi/kit/issues/258)). If one `kit update` has been downloading for over an hour, another `kit update` run in the same directory can remove its staged download ([#226](https://github.com/akonwi/kit/issues/226)). The terminal client can still panic while opening a session, in the background syntax highlighter ([#210](https://github.com/akonwi/kit/issues/210)). Subagent live streams still drop single events over 16 KiB until the subagent's transcript reloads ([#209](https://github.com/akonwi/kit/issues/209)), and one invalid event still fails every page of a subagent's live stream that holds it ([#208](https://github.com/akonwi/kit/issues/208)).

macOS CLI archives require macOS 14 or newer. Linux archives are built on Ubuntu 24.04 with a glibc 2.39 baseline and are not fully static. Windows and npm distribution are unsupported.
