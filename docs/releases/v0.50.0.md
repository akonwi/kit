# Kit 0.50.0

The agent can now open web pages in the macOS app's browser and, through tools the app hosts, read and act on the app's browser tabs. Plugins can ask attached clients to open a page. Clients can view files outside the session's working directory, and Markdown files open rendered. The session protocol moves from 48 to 49, so upgrade the server and Kit for macOS together: Kit for macOS 0.6.1 and older can't attach to a 0.50.0 server, and Kit for macOS 0.7.0 needs a 0.50.0 or newer server (see the upgrade guide). The native macOS app is released separately and is not included in CLI archives.

## What's changed

- `c701cca2` — feat(core,macos): let the model open URLs in the Mac app's browser
  - The primary agent has a new `open_url` tool. The server accepts an absolute `http` or `https` URL with a host and no credentials, records its canonical form in the result, and returns `true` without waiting for any client. The result doesn't say whether a page opened.
  - Kit for macOS 0.7.0 opens the page in its browser when it sees the call complete live. It never opens pages for calls it reads from the transcript, replays, or catches up on after reconnecting. The terminal client doesn't open these pages. Subagents don't get the tool.
  - No wire change: the existing `tool.completed` event carries the tool's name and details.
- `407b798d` — feat(core,macos): let plugins open URLs in the Mac app's browser (#276)
  - Plugins can call `kit/system/open-url` with `{ "url": "..." }`. Kit checks the address with the `open_url` rules, then returns `null` once it has published the request. It doesn't wait for a client or report whether a page opened. A session's plugins can make five requests in ten seconds; more fail with `-32006` and `data.reason` `rate_limited`. A plugin can only reach its own session. See [URL requests](https://github.com/akonwi/kit/blob/main/apps/web/docs/plugin-protocol/native-v2.md#url-requests) and [ADR 0049](https://github.com/akonwi/kit/blob/main/docs/adrs/0049-let-plugins-ask-attached-clients-to-open-web-pages.md).
  - The session publishes the new live event `url.open.requested`. It is never in a snapshot or the transcript, and only streams open when the request was made receive its address. This is the protocol 49 change.
  - The terminal client ignores these requests.
- `e8d8b60d` — feat: view files outside the session's working directory (#277)
  - The new `readHostFile` session operation (`POST /v1/sessions/{id}/host-files/read`) reads any file on the session's server, given an absolute or `~/` path. Text comes back as a bounded preview with the workspace preview limits. PNG, JPEG, GIF, and WebP images come back whole, up to 16 MiB and 24 megapixels. Other files fail with `binary_file`, and directories, devices, sockets, and FIFOs fail with `not_file`. Any credential that can use a session can already run shell commands as the server's user, so this adds no access. See [ADR 0050](https://github.com/akonwi/kit/blob/main/docs/adrs/0050-view-files-outside-the-working-directory.md).
  - In the terminal client, tool rows that name files outside the working directory open them in a host File tab, and the `Ctrl+O` picker accepts a typed path. Host text files can't be annotated. Host images are fitted to the pane, centred, keeping their proportions. Failures say why.
  - The Go client's `Session.ReadHostFile` reports an `UnsupportedError` against a server that doesn't have the operation.
  - Workspace errors without details now omit the `details` member instead of sending `null`, which clients decoding declared errors rejected.
- `2a76ad54` — feat: preview Markdown files rendered (#278)
  - Markdown files open rendered in file tabs, in the terminal client and the macOS app. In the terminal client, the toggle in the tab's header switches between `Preview` and `Source`. A file opened at a line, such as from a tool row, opens as source at that line. A file too complex to parse within the parser's budget shows its source, with `Too large to render; showing source` in the footer.
  - In the preview, a `+` in the margin anchors an annotation to a whole block. Saved annotations show under their block.
  - A syntax-highlighting parse cancelled at the wrong moment could make the next parse abort the process. Kit now replaces the parser after a parse stops.
  - See [Markdown files](https://github.com/akonwi/kit/blob/main/docs/features/markdown-files.md).
- `cd8ca5ba` — feat(core,macos): let the model use the Mac app's browser through client-hosted session plugins
  - Attached clients can now host session plugins that provide tools ([ADR 0051](https://github.com/akonwi/kit/blob/main/docs/adrs/0051-let-attached-clients-host-session-plugins.md)). A client declares an instance with `attachClientPlugin` (`PUT /v1/sessions/{sessionID}/client-plugins/{instanceID}`), opens its session event stream with `clientPlugin={instanceID}`, receives `client_plugin.call.requested` events, and answers with `completeClientPluginCall`. `detachClientPlugin` removes the instance, and `client_plugin.call.resolved` reports how each call ended. The server validates each call against the declared schema, and the tools reach the session's primary agent and its subagents. A client instance provides tools only, and stays available for 10 seconds after its stream closes.
  - Kit for macOS 0.7.0 hosts a `browser` plugin over a session tab's browser tabs. Its tools appear only while the app has that session open.
  - Images in plugin tool results are kept as session attachments, so clients can show them.
  - These are the remaining protocol 49 changes.
- `4745cff0`, `b1eb5728`, `ef0f8a56`, `10b795b4`, `971085a9`, and `3a757461`, plus the macOS parts of the commits above, are macOS app changes. They ship in the macOS app's own release, not in this CLI. `24bed50b` and `0a5db523` update contributor docs.

## Upgrade guide

Kit 0.50.0 moves the session protocol from 48 to 49. Clients and servers connect only when they speak the same protocol, so:

- Kit 0.47.0 through 0.49.1 can't attach to a 0.50.0 server, and a 0.50.0 client refuses a running 0.47.0–0.49.1 server. A 0.50.0 client leaves that server running and says which side to update; it won't replace it on its own.
- Kit for macOS 0.6.1 and older can't attach to a 0.50.0 server. Kit for macOS 0.7.0 needs a 0.50.0 or newer server.

Let active work settle, then upgrade Kit and restart the server. From 0.49.0 or 0.49.1, run:

```sh
kit update
```

It installs 0.50.0 (with `brew upgrade akonwi/tap/kit` if Kit came from Homebrew), then offers to restart this home's server, saying how many sessions the restart interrupts. From 0.48.0 or older, or to do it by hand:

```sh
brew update && brew upgrade akonwi/tap/kit
kit server restart
kit version
kit server status
```

Then upgrade Kit for macOS to 0.7.0 if you use it. This release adds no database migration.

Servers on other machines, reached over SSH, Tailscale, or pairing, are never changed by `kit update` here. Upgrade Kit on each of those machines and restart its server, and upgrade every client that attaches to it.

**Plugin authors:** existing plugins keep working; the plugin protocol only adds the `kit/system/open-url` method. Requests open pages only in Kit for macOS 0.7.0 or newer; the terminal client ignores them, and nothing tells the plugin whether a page opened.

**Client and Go program authors:** update `github.com/akonwi/kit/api` to v0.50.0, which speaks protocol 49. The changes are additive:

- **New events** in the session event union: `url.open.requested` (`URLOpenRequestedEvent`), `client_plugin.call.requested` (`ClientPluginCallRequestedEvent`), and `client_plugin.call.resolved` (`ClientPluginCallResolvedEvent`). Code that switches over event kinds should handle or ignore them.
- **New methods:** `Session.ReadHostFile` reads a file on the server. `Session.HostPlugin` attaches a client-hosted plugin instance and returns its bound event stream, `Session.CompleteClientPluginCall` answers a call, and `Session.DetachPlugin` removes the instance.

## Compatibility and limitations

The session protocol is 49. Clients and servers from 0.50.0 work together; earlier releases don't work with them (see the upgrade guide). Kit for macOS 0.7.0 is the first app release that can use a 0.50.0 server.

Only Kit for macOS opens pages from `open_url` and `kit/system/open-url`, and only if it is attached to the session when the request is made. The terminal client ignores them, and no client confirms them, so the model or plugin can't tell whether anything opened. There is no confirmation prompt before the app opens a page. The browser tools exist only while Kit for macOS has the session open; a session used only from the terminal client doesn't have them.

`kit update` from a published 0.49.x to 0.50.0 hasn't been tested end to end. Known issues: dismissing a subagent just as it finishes can leave its stored conversation until the server restarts ([#258](https://github.com/akonwi/kit/issues/258)). `kit update` treats `/dev/null` as a terminal and exits 0 instead of 2 ([#272](https://github.com/akonwi/kit/issues/272)). If one `kit update` has been downloading for over an hour, another `kit update` run in the same directory can remove its staged download ([#226](https://github.com/akonwi/kit/issues/226)). The terminal client can still panic while opening a session, in the background syntax highlighter ([#210](https://github.com/akonwi/kit/issues/210)). Subagent live streams still drop single events over 16 KiB until the subagent's transcript reloads ([#209](https://github.com/akonwi/kit/issues/209)), and one invalid event still fails every page of a subagent's live stream that holds it ([#208](https://github.com/akonwi/kit/issues/208)).

macOS CLI archives require macOS 14 or newer. Linux archives are built on Ubuntu 24.04 with a glibc 2.39 baseline and are not fully static. Windows and npm distribution are unsupported.
