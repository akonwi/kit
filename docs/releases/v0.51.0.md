# Kit 0.51.0

Every client attached to a session now sees, as it happens, the changes another client makes: renames, model and thinking-level changes, the follow-up queue, and compaction. A queued follow-up that can't start now holds the queue and says why, instead of silently blocking the session. Every failed context compaction now says why it failed, live and after a reconnect or restart. The session protocol moves from 49 to 50, so upgrade the server and Kit for macOS together: Kit for macOS 0.7.0 and older can't attach to a 0.51.0 server, and Kit for macOS 0.8.0 needs a 0.51.0 or newer server (see the upgrade guide). The native macOS app is released separately and is not included in CLI archives.

## What's changed

- `7138e8c2` — feat(session): tell every attached client about session changes ([#106](https://github.com/akonwi/kit/issues/106))
  - The session's live stream carries two new session-scoped events: `session.configuration.changed`, with the applied model, thinking level, accepted inputs, and configuration revision, and `follow_ups.changed`, with the whole follow-up queue. Compaction outside a turn, which a client requested or a model change needed, is reported as `compaction.started` and `compaction.completed` with no turn. See [ADR 0052](https://github.com/akonwi/kit/blob/main/docs/adrs/0052-tell-every-attached-client-about-session-changes.md).
  - A queued prompt leaves the queue in the same step that starts its turn, so no snapshot shows it both queued and running.
  - A queued prompt that can't start when its turn comes (for example, an attachment it names is gone) now holds the queue. The queue's new `admissionFailure` says why, `follow_ups.changed` announces it, and snapshots carry it until the queue is restored. New prompts are refused while it's held. Restoring the queue returns the prompts to the composer and unblocks the session; a later turn's end also retries the held prompt.
  - A prompt that loses admission to a holder that starts no turn, such as a subagent mailbox, now starts when the holder lets go. Prompts queued behind a turn resumed when the session loads start when that turn ends.
  - Queue previews and other event text are single-line, renderer-safe text, and the server checks each event against the rules clients apply before it enters the stream.
  - The terminal client applies renames, configuration, queue, and compaction changes from other clients as they arrive, and takes the queue only from the stream and snapshots. A held queue shows `N held · ↑ restore` in the footer and `Queued message couldn't start: <reason>` in the pending row, with a one-time warning toast. A prompt refused behind a held queue says to restore the queue first.
  - Behavior change: a compaction or model change that another client requested no longer raises a toast in this client when it fails; the client that asked reports it.
  - These are the protocol 50 changes, together with the next item's.
- `a7a5c6ad` — feat(session): classify compaction failure reasons ([#107](https://github.com/akonwi/kit/issues/107))
  - Every failed compaction now carries exactly one reason instead of provider text or a generic message: `summary_truncated`, `summary_invalid`, `policy_stop`, `provider_error`, `not_adaptable`, `canceled`, `conflict`, or `internal_error`. Provider messages, request IDs, and prompt or summary content stay in the server log. See [ADR 0053](https://github.com/akonwi/kit/blob/main/docs/adrs/0053-classify-compaction-failures.md).
  - A failed `compaction.completed` carries `compactionFailureReason` and no longer carries `errorMessage`. A turn that compaction failed carries `compactionFailureReason` on `turn.completed`, `TurnInfo`, and `PromptOutcome`, alongside its usual error message. The reason is stored with the turn, so `GET …/turns/{turnID}` explains the failure after a reconnect or server restart.
  - `compactSession`, and `configureSession` when a model change needs compaction, answer a failed compaction with HTTP 422 and the new error code `compaction_failed`, whose details are `{"reason": …}`, instead of `unprocessable`. A compaction refused as busy or conflicting, or canceled by its request or a closing session, isn't answered as `compaction_failed`.
  - The terminal client and `kit --print` explain each reason in one sentence, for example "Context compaction failed. The summary was longer than the compaction model's output limit."
  - In `droids`, `CompactContext` returns a `*CompactionError` with the reason, the durable `compaction.failed` event records it, and a turn that compaction failed records it as `DroidError.CompactionFailure`.
- `a6c40851`, `623b5a17`, `84530eca`, and `b0fca6cf`, plus the macOS parts of the commits above, are macOS app changes. They ship in the macOS app's own release, not in this CLI. `c8ad53fe` adds a design record (ADR 0054) for figures drawn from fenced Markdown; it doesn't change Kit's behavior in this release.

## Upgrade guide

Kit 0.51.0 moves the session protocol from 49 to 50. Clients and servers connect only when they speak the same protocol, so:

- Kit 0.50.0 can't attach to a 0.51.0 server, and a 0.51.0 client refuses a running 0.50.0 or older server. A 0.51.0 client leaves that server running and says which side to update; it won't replace it on its own.
- Kit for macOS 0.7.0 and older can't attach to a 0.51.0 server. Kit for macOS 0.8.0 needs a 0.51.0 or newer server.

Let active work settle, then upgrade Kit and restart the server. From 0.49.0 or newer, run:

```sh
kit update
```

It installs 0.51.0 (with `brew upgrade akonwi/tap/kit` if Kit came from Homebrew), then offers to restart this home's server, saying how many sessions the restart interrupts. From 0.48.0 or older, or to do it by hand:

```sh
brew update && brew upgrade akonwi/tap/kit
kit server restart
kit version
kit server status
```

Then upgrade Kit for macOS to 0.8.0 if you use it. This release adds no database migration.

Servers on other machines, reached over SSH, Tailscale, or pairing, are never changed by `kit update` here. Upgrade Kit on each of those machines and restart its server, and upgrade every client that attaches to it.

**Plugin authors:** the plugin protocol doesn't change, and existing plugins keep working.

**Client and Go program authors:** update `github.com/akonwi/kit/api` to v0.51.0, which speaks protocol 50.

- **New events** in the session event union: `session.configuration.changed` (`SessionConfigurationChangedEvent`, with a `*SessionConfiguration`) and `follow_ups.changed` (`FollowUpsChangedEvent`, with a `*FollowUpQueue`). Code that switches over event kinds should handle or ignore them. A client that shows the queue should take it from these events and snapshots, not from a queue operation's response, which may arrive after a newer queue.
- **Turn-less compaction:** `compaction.started` and `compaction.completed` may now have an empty `TurnID`, for compaction outside a turn. Don't assume they belong to the running turn.
- **Held queues:** `FollowUpQueue.AdmissionFailure` (`*FollowUpAdmissionFailure`, with a `Message`) is set while the first queued prompt can't start. Show it and offer `RestoreFollowUps`; new prompts fail while it's set.
- **`errorMessage` → `compactionFailureReason`:** `CompactionCompletedEvent.ErrorMessage` is removed. Read `CompactionCompletedEvent.CompactionFailureReason` instead; it's empty when the compaction succeeded. `TurnCompletedEvent`, `TurnInfo`, and `PromptOutcome` gain `CompactionFailureReason` on a failed turn; their `ErrorMessage` stays. The reason is a closed `CompactionFailureReason` enum with `CompactionFailure…` constants and `Valid()`; the client rejects a reason it doesn't declare, so word each known reason yourself.

  ```go
  case protocol.CompactionCompletedEvent:
      if e.CompactionFailureReason != "" { // was: e.ErrorMessage != ""
          showCompactionFailure(e.CompactionFailureReason)
      }
  ```
- **Operation errors:** `Session.Compact`, and `Session.Configure` when a model change needs compaction, fail with a `*ServerError` whose code is `ErrorCompactionFailed` (`compaction_failed`) and whose details are `CompactionFailedErrorDetails{Reason}`, instead of `unprocessable`. Use `kit.CompactionFailure(err)` to get the reason:

  ```go
  if reason, ok := kit.CompactionFailure(err); ok {
      showCompactionFailure(reason)
  }
  ```

**`droids` SDK users:** a compaction failure is now a `*CompactionError` with a `Reason` (`CompactionFailureReason`) and a diagnostic `Cause`; use `droids.CompactionFailureOf(err)` to read it. A turn that compaction failed records the reason in `DroidError.CompactionFailure`, and the durable `compaction.failed` event records it as `reason`. Failures recorded before this release have no reason.

## Compatibility and limitations

The session protocol is 50. Clients and servers from 0.51.0 work together; earlier releases don't work with them (see the upgrade guide). Kit for macOS 0.8.0 is the first app release that can use a 0.51.0 server.

Adding a compaction failure reason is a protocol change, because clients decode the vocabulary strictly. Snapshots don't keep a history of past compaction failures outside a turn; those are explained live and in the operation's response. Reloading a session's configuration and prompt sources isn't announced; other clients see it at their next snapshot.

`kit update` from a published 0.50.0 to 0.51.0 hasn't been tested end to end. Known issues: dismissing a subagent just as it finishes can leave its stored conversation until the server restarts ([#258](https://github.com/akonwi/kit/issues/258)). `kit update` treats `/dev/null` as a terminal and exits 0 instead of 2 ([#272](https://github.com/akonwi/kit/issues/272)). If one `kit update` has been downloading for over an hour, another `kit update` run in the same directory can remove its staged download ([#226](https://github.com/akonwi/kit/issues/226)). The terminal client can still panic while opening a session, in the background syntax highlighter ([#210](https://github.com/akonwi/kit/issues/210)). Subagent live streams still drop single events over 16 KiB until the subagent's transcript reloads ([#209](https://github.com/akonwi/kit/issues/209)), and one invalid event still fails every page of a subagent's live stream that holds it ([#208](https://github.com/akonwi/kit/issues/208)). Turn-end events still carry a generic failure reason for failures other than compaction ([#240](https://github.com/akonwi/kit/issues/240)).

macOS CLI archives require macOS 14 or newer. Linux archives are built on Ubuntu 24.04 with a glibc 2.39 baseline and are not fully static. Windows and npm distribution are unsupported.
