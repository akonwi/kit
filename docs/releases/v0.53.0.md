# Kit 0.53.0

Models can now save images that tools return as files. A plugin tool's result names each image Kit keeps as a session attachment, and the new built-in `save_attachment` tool copies an attachment the session owns to a file on the server, such as an in-app browser screenshot saved into a repository or handed to another tool. Subagents get the tool too. The session protocol stays 50, so this release works with Kit 0.52.0 clients and servers and with Kit for macOS 0.8.0 and 0.9.0; restart the server to give models the new tool. The native macOS app is released separately and is not included in CLI archives.

## What's changed

- `1ccb4934` — feat(session): let the model save tool images with save_attachment
  - When a plugin tool's image is kept as a session attachment, the tool result follows it with one line giving the attachment ID, media type, dimensions, and size, and pointing to `save_attachment`. An image Kit couldn't keep gets a line saying so. This applies to plugins that run as processes and to tools hosted by an attached client, such as the macOS app's in-app browser.
  - The new `save_attachment(attachment, path, overwrite?)` model tool copies an attachment the session owns to a file on the server. A relative path resolves from the session's working directory, `~` is the server user's home, and missing parent directories are created. The tool refuses paths within the Kit home, including through symbolic links in the path. It also refuses a destination that is a symbolic link, a directory, or anything else that isn't a regular file, and an existing file unless `overwrite` is set. It checks the copy against the attachment's recorded size and SHA-256 and writes it atomically, with mode 0644. A fork can save the attachments it inherited.
  - Subagents get `save_attachment` too, reading their owning session's attachments, where images from client-hosted tools they call are kept, and resolving relative paths from the subagent's working directory.
  - See [ADR 0055](https://github.com/akonwi/kit/blob/main/docs/adrs/0055-let-the-model-save-session-attachments-to-files.md) and [Attachments](https://github.com/akonwi/kit/blob/main/docs/features/attachments.md#save_attachment).
- `328d6ed2` — docs(skills): count both embedded skills in the registry limit

## Compatibility and limitations

The session protocol stays 50, and the API, plugin protocol, and `droids` SDK don't change. Kit 0.53.0 clients and servers work with Kit 0.52.0 clients and servers, and with Kit for macOS 0.8.0 and newer. No upgrade steps are needed beyond the usual `kit update` (or `brew upgrade akonwi/tap/kit`) and a server restart; this release adds no database migration.

The attachment lines and `save_attachment` come from the server, so models get them only after the server restarts on 0.53.0. Images that MCP tools return still aren't kept as attachments, so they have no attachment line and `save_attachment` can't copy them. A saved file contains whatever the image showed, including page content or values on screen; the model chooses where it goes, as with any file it writes.

`save_attachment` is a new built-in tool name. Plugin tool names always have the form `<plugin>__<tool>`, so they can't collide with it. An MCP server's tool is named after the server, lowercased with other characters replaced by `_`, so a server named `save_attachment` or `Save Attachment` now collides with the built-in tool, and sessions that load that server fail to open with a duplicate tool name error. Rename such a server in your MCP configuration before restarting the server.

Known issues: dismissing a subagent just as it finishes can leave its stored conversation until the server restarts ([#258](https://github.com/akonwi/kit/issues/258)). `kit update` treats `/dev/null` as a terminal and exits 0 instead of 2 ([#272](https://github.com/akonwi/kit/issues/272)). If one `kit update` has been downloading for over an hour, another `kit update` run in the same directory can remove its staged download ([#226](https://github.com/akonwi/kit/issues/226)). The terminal client can still panic while opening a session, in the background syntax highlighter ([#210](https://github.com/akonwi/kit/issues/210)). Subagent live streams still drop single events over 16 KiB until the subagent's transcript reloads ([#209](https://github.com/akonwi/kit/issues/209)), and one invalid event still fails every page of a subagent's live stream that holds it ([#208](https://github.com/akonwi/kit/issues/208)). Turn-end events still carry a generic failure reason for failures other than compaction ([#240](https://github.com/akonwi/kit/issues/240)).

macOS CLI archives require macOS 14 or newer. Linux archives are built on Ubuntu 24.04 with a glibc 2.39 baseline and are not fully static. Windows and npm distribution are unsupported.
