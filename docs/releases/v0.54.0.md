# Kit 0.54.0

The server now keeps its model catalog fresh. It refreshes the models.dev catalog in the background when it starts and about once a day after that, so pickers list new models without a manual **Refresh models**. Models the catalog drops leave the pickers but keep working wherever they're already in use. When a provider rejects a request, Kit now shows the provider's own reason next to its description. Annotating a range that ends on a blank line works again, and the terminal client opens a changed file from its Diff header. The session protocol stays 50, so this release works with Kit 0.51.0 and newer clients and servers and with Kit for macOS 0.8.0 and newer; restart the server to get the server-side changes. The native macOS app is released separately and is not included in CLI archives.

## What's changed

- `22eca936` — feat(server): refresh the model catalog in the background ([#117](https://github.com/akonwi/kit/issues/117))
  - The long-lived server (`kit __server`, which `kit` starts as a daemon, and `kit server run`) refreshes the OpenAI, Anthropic, OpenCode Zen, and OpenCode Go catalogs from models.dev once when it starts, then whenever the catalog it holds is a day old, checking hourly by wall-clock time. Each refresh takes at most 30 seconds, and startup, attaching, and prompts never wait for it. A failed refresh, such as when offline, keeps the catalog the server has, logs a warning, and is retried at the next hourly check. A successful refresh replaces `$KIT_HOME/.cache/models.dev.json`. Print mode and one-shot commands never fetch the catalog themselves.
  - Each models.dev provider now lists exactly the models of the latest catalog: added models appear, changed names and limits update, and models the catalog no longer lists leave the pickers. A catalog with no usable models for a provider leaves that provider's list unchanged.
  - A model that leaves the listing keeps working where it's already used. Sessions, subagents, subagent definitions, and the compaction model keep resolving and streaming it and can still change its thinking level. New choices accept only listed models, so switching a session or subagent to a retired model, or picking it as a default, compaction, or override model, is refused.
  - See [Model catalog](https://github.com/akonwi/kit/blob/main/docs/features/model-catalog.md) and [ADR 0057](https://github.com/akonwi/kit/blob/main/docs/adrs/0057-keep-the-model-catalog-fresh.md).
- `f0b62cb5` — fix(droids): keep the provider's reason when it rejects a request ([#116](https://github.com/akonwi/kit/issues/116))
  - A rejected request now reads like `Provider rejected the request: Upstream request failed: Model is unavailable. (HTTP 400)`: Kit's description, then the provider's explanation and the HTTP status of its response. The terminal client, print mode, and the macOS app show it, and it's stored with the failed reply, so it's still there after a reload or a server restart. A failure that didn't come from a provider response, such as a lost connection, shows only Kit's description.
  - Kit keeps only the explanation fields of a provider's error response, as one line of at most 300 bytes without control or bidirectional characters. HTML error pages and malformed bodies add no explanation.
  - Codex 4xx responses are now treated as rejected requests instead of being retried, and OpenCode Chat Completions failures are classified by HTTP status first, recognizing context-window rejections.
  - The `droids` SDK's `ProviderError` gains `Status` and `Detail`, and `ProviderError.Explanation` and `AssistantMessage.ErrorExplanation` join them for display. `Message` stays Kit's fixed description. See [Provider rejections](https://github.com/akonwi/kit/blob/main/docs/features/provider-rejections.md) and the [`droids` SDK](https://github.com/akonwi/kit/blob/main/docs/droids-sdk.md).
- `185830d3` — fix(annotation): keep blank lines at the end of an annotated range
  - Annotating a multi-line range that ends on a blank line used to drop the last line and fail as stale with a server error. Blank lines at either edge of a range, and a final line without a newline, now keep their place, and CRLF lines are previewed without their CR.
  - An annotation whose range no longer matches the file now returns the declared 409 conflict (`stale_file` when the evidence no longer covers the range) instead of a 500, so clients keep the draft and offer a refresh.
- `04756465` — fix(workingdiff): remove the isolated git home when the service closes
  - The server's diff service no longer leaves a `kit-diff-git-*` directory in the temporary directory each time the server starts. It removes the directory when the server stops, after cancelling and waiting for any git commands it's running. Directories that earlier releases left behind aren't removed; you can delete them from `$TMPDIR`.
- `4e8d252b` — feat(macos,tui): open a changed file from its Diff header
  - In the terminal client, clicking a file's path in its Diff section header opens or selects that file's tab without closing the Diff; clicking the rest of the header still folds the file. The path is underlined under the pointer, and deleted or non-regular files have no link. While the Diff shows the working tree, the file opens at its first change; for a commit or branch it opens at the top, since the tab shows the working-tree file.

The source tree now also contains a native iOS client (`apps/ios`) and a Swift package shared by the Apple clients (`apps/apple`). Neither is part of this release.

## Compatibility and limitations

The session protocol stays 50, and the session API and plugin protocol don't change. Kit 0.54.0 clients and servers work with Kit 0.51.0 and newer clients and servers, and with Kit for macOS 0.8.0 and newer. The `droids` SDK change is additive. No upgrade steps are needed beyond the usual `kit update` (or `brew upgrade akonwi/tap/kit`) and a server restart; this release adds no database migration.

The catalog refresh, provider reasons, annotation fixes, and temporary-directory cleanup all run in the server, so they apply only after the server restarts on 0.54.0. The server now contacts `https://models.dev/api.json` on its own at startup and about daily; earlier releases fetched it only when asked to refresh models. A retired model that the release embeds stays usable until the next release, but one that only an earlier refresh added stays usable only until the server restarts.

Known issues: dismissing a subagent just as it finishes can leave its stored conversation until the server restarts ([#258](https://github.com/akonwi/kit/issues/258)). `kit update` treats `/dev/null` as a terminal and exits 0 instead of 2 ([#272](https://github.com/akonwi/kit/issues/272)). If one `kit update` has been downloading for over an hour, another `kit update` run in the same directory can remove its staged download ([#226](https://github.com/akonwi/kit/issues/226)). The terminal client can still panic while opening a session, in the background syntax highlighter ([#210](https://github.com/akonwi/kit/issues/210)). Subagent live streams still drop single events over 16 KiB until the subagent's transcript reloads ([#209](https://github.com/akonwi/kit/issues/209)), and one invalid event still fails every page of a subagent's live stream that holds it ([#208](https://github.com/akonwi/kit/issues/208)). Turn-end events still carry a generic failure reason for failures other than compaction ([#240](https://github.com/akonwi/kit/issues/240)), although a provider rejection's stored reply now carries the provider's reason.

macOS CLI archives require macOS 14 or newer. Linux archives are built on Ubuntu 24.04 with a glibc 2.39 baseline and are not fully static. Windows and npm distribution are unsupported.
