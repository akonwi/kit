# Kit 0.56.0

Kit shows a pull request's CI checks. The server shares the checks it already observes for the session's branch with clients and plugins: the terminal client's footer shows them after the PR label, plugins receive them as `git.pullRequest.checks`, and clients can stream them from a new session endpoint. The OpenAPI contract now describes every session event. The plugin protocol's documentation and JSON schemas moved to `docs/plugin-protocol`; plugin authors should update their manifests' `$schema` URL. The session protocol stays 50, so this release works with Kit 0.51.0 and newer clients and servers and with Kit for macOS 0.8.0 and newer; restart the server to get the server-side changes. The native macOS app is released separately and is not included in CLI archives.

## What's changed

- `a68a38c1` — feat(vcs): share observed pull request checks with clients and plugins ([#282](https://github.com/akonwi/kit/pull/282))
  - The server summarizes the checks of the branch's pull request: an overall state (`failing` when any check failed or was canceled, otherwise `pending` while any runs, otherwise `passing` when any passed, otherwise `none`), the state of the repository's required checks, counts by state, and at most 50 checks, failing first. It builds the summary from the `gh` observation the session already keeps for its agent, so no extra GitHub requests are made. Without an installed, authenticated `gh` there is no pull request and so no checks.
  - The terminal client shows the checks after the footer's location, as `~/kit (feature* · PR #74) · ✗ 10/12`: `✓` passing, `✗` failing, or `●` running, in the state's color, with passed/total (skipped checks excluded), linking to the pull request's checks page. When the footer narrows, the directory shortens first, then the count is dropped and the glyph stays.
  - Plugins receive the summary as the optional `git.pullRequest.checks` in initialization and in `kit/events/git.changed`, and a change in any check's state sends `git.changed`. This is an additive v1 field: plugins may ignore it, and strict schema validators must use the updated `protocol.schema.json`.
  - Clients stream the status from `GET /v1/sessions/{sessionID}/pull-request/events` (`streamSessionPullRequest`): the current status first, then deduplicated latest-only `pullRequest.status` records. The Go session client adds `Session.WatchPullRequest`, which returns an `UnsupportedError` against a server without the stream. See [VCS status](https://github.com/akonwi/kit/blob/main/docs/features/vcs-status.md#pull-request-checks) and [ADR 0060](https://github.com/akonwi/kit/blob/main/docs/adrs/0060-share-observed-pull-request-checks-with-clients-and-plugins.md).
- `1bd07a37` — feat(api): describe session event payloads in the OpenAPI contract
  - `SessionEvent` in `api/kit-session.openapi.json` is now the closed union of its 35 kinds, a `oneOf` with a `kind` discriminator, each variant listing its payload members. Before, it listed only the four identity members, which no emitted event matched. The wire is unchanged; clients generated from the contract can now decode events by kind.
  - The Go session client no longer rejects two valid events the server sends: a context change whose `contextTokens` is 0, and a boundary whose truncation left no content. Both members are now optional in the contract.
- `b7d51050` — Plugin protocol documents and schemas moved
  - **The plugin protocol moved** from `apps/web/docs/plugin-protocol` to [`docs/plugin-protocol`](https://github.com/akonwi/kit/tree/main/docs/plugin-protocol): the v1 and native v2 documents and the manifest and protocol schemas. The schemas' `$id`s are now `https://raw.githubusercontent.com/akonwi/kit/main/docs/plugin-protocol/manifest.schema.json` and `…/protocol.schema.json`, and the old `apps/web/…` URLs no longer resolve on `main`. Point your `plugin.json` `$schema` and any schema validation at the new URLs. Kit accepts any absolute `$schema` URI in a manifest, so existing plugins keep loading unchanged.

The source tree's native iOS client (`apps/ios`) also gained features in this period, and the shared Swift package and macOS app changed. They aren't part of this release.

## Compatibility and limitations

The session protocol stays 50. The pull request stream is a new, additive endpoint, and the event union describes events the wire already carried. Kit 0.56.0 clients and servers work with Kit 0.51.0 and newer clients and servers, and with Kit for macOS 0.8.0 and newer. No upgrade steps are needed beyond the usual `kit update` (or `brew upgrade akonwi/tap/kit`) and a server restart; this release adds no database migration.

Check status needs a 0.56.0 server: older servers answer the pull request stream with a 404, and a 0.56.0 terminal client attached to one shows no checks. Plugins receive `git.pullRequest.checks` only from a 0.56.0 server, and only when `gh` is installed and authenticated. Kit for macOS shows checks from 0.13.0. The iOS client doesn't show them.

Known issues: dismissing a subagent just as it finishes can leave its stored conversation until the server restarts ([#258](https://github.com/akonwi/kit/issues/258)). `kit update` treats `/dev/null` as a terminal and exits 0 instead of 2 ([#272](https://github.com/akonwi/kit/issues/272)). If one `kit update` has been downloading for over an hour, another `kit update` run in the same directory can remove its staged download ([#226](https://github.com/akonwi/kit/issues/226)). The terminal client can still panic while opening a session, in the background syntax highlighter ([#210](https://github.com/akonwi/kit/issues/210)). Subagent live streams still drop single events over 16 KiB until the subagent's transcript reloads ([#209](https://github.com/akonwi/kit/issues/209)), and one invalid event still fails every page of a subagent's live stream that holds it ([#208](https://github.com/akonwi/kit/issues/208)). Turn-end events still carry a generic failure reason for failures other than compaction ([#240](https://github.com/akonwi/kit/issues/240)).

macOS CLI archives require macOS 14 or newer. Linux archives are built on Ubuntu 24.04 with a glibc 2.39 baseline and are not fully static. Windows and npm distribution are unsupported.
