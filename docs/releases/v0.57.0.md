# Kit 0.57.0

Kit now ships a browser client. The server serves it on the same address as its session API, so an Android phone, or any browser on a machine without Kit, can pair with a server and work in its sessions: the sessions list, the live transcript and composer, attachments, interaction answers, changes with line comments, and files. The server also colors code for clients, lists sessions with the ones waiting on you first, and reports session errors in the documented error body, so the terminal client and `kit print` show the server's reason instead of "daemon returned malformed operation error". Ard source highlights `.*`, `&T` and `&mut T`, field shorthand, and struct tags. The session protocol stays 50, so this release works with Kit 0.51.0 and newer clients and servers and with Kit for macOS 0.8.0 and newer; restart the server to get the browser client and the server-side changes. The native macOS app is released separately and is not included in CLI archives.

## Open the browser client

The browser reaches the server the same way any other device does: on a tailnet (`kit server expose --tailscale`), through a reverse proxy or tunnel, or through an SSH port forward. A browser on the server's own machine can use the loopback address.

1. On the server's machine, run `kit server pair` (or use **Pair a Device** in the Mac app's server settings, or the **pair** command in the TUI's command palette). It prints a pairing link for each address the server's settings name (`server.allowedHosts`, `server.allowedOrigins`), for each `--url` you pass, and for its loopback address, and a QR code of the first.
2. Open the link in the browser, or scan the QR code with the phone.
3. Name the browser and choose **Pair**.

A link works once and expires after 5 minutes. On a phone, **Add to Home Screen** opens the client without browser controls. Use `https`, or plain `http` only on a private network such as a tailnet: over `http` to another machine, the pairing code and device token travel unencrypted. **Sign out** in the Sessions menu revokes the browser's device; `kit server devices revoke NAME` does the same from the server. See [Browser client](https://github.com/akonwi/kit/blob/main/docs/features/browser-client.md) and [Pairing devices](https://github.com/akonwi/kit/blob/main/docs/features/pairing.md).

## What's changed

- `2562b714` — feat(web): revive the browser client
  - The browser client ([ADR 0059](https://github.com/akonwi/kit/blob/main/docs/adrs/0059-serve-a-browser-client-from-the-kit-server.md)) is built into the `kit` executable and served at the server's `/`, `/pair`, and `/sessions/{id}`. Kit 0.56.0 served a placeholder page there, and earlier releases nothing.
  - **Sessions** lists the server's sessions in attention order; **Needs you** shows only those waiting on a confirmation, a question, or a sign-in, and **New session** starts one in a folder with a model, thinking level, and name. The session menu shows the context used, changes the model and thinking level, and compacts, renames, forks, and deletes the session.
  - A session shows its transcript live: Markdown replies, tool calls grouped under each reply, and turns that stopped or failed. The composer sends prompts, queues follow-ups while a turn runs, and **Stop** ends the turn. When a session needs an answer, the composer gives way to it.
  - Photo and file attachments; images Kit shows; `!` and `!!` shell commands.
  - Replies draw GitHub callouts, code blocks with **Copy** colored by the server's highlighter, data figures, and Mermaid flowcharts and sequence diagrams.
  - Pages run under a strict Content Security Policy, and model output is never rendered as HTML.
- `502501e8` — feat(web): read changes and comment on lines
  - **Changes**, in the session menu, shows uncommitted changes, the branch, or a commit, file by file, colored by the server. Tapping line numbers selects lines to comment on. Comments go with the next message as file annotations, can be edited or deleted, and show as cards in the sent message; a comment whose lines changed blocks sending until it is moved to new lines or deleted.
- `e149d53d` — feat(web): open files and comment on file lines
  - **Open File…** searches the session folder's files. A file also opens from Read and Edit tool calls, Changes rows, and comments. It shows highlighted source at a line, or Markdown as a preview, and takes comments on line ranges.
- `4acedbc0` — feat(server): serve syntax highlighting to clients ([ADR 0062](https://github.com/akonwi/kit/blob/main/docs/adrs/0062-serve-syntax-highlighting-to-clients.md))
  - A new `highlightCode` operation (`POST /v1/highlight`) colors code blocks with the server's Tree-sitter grammars, as per-line UTF-16 `[start, length, role]` triples and a role table. A request holds at most 128 blocks, 512 KiB of source per block, 768 KiB in total, and 64 bytes per language label, within the session API's request body limit; over those bounds it is rejected as `limit_exceeded`.
  - `readWorkspaceFile`, `readHostFile`, and `readFileDiff` accept an optional `highlight` flag and then return the coloring with the content; a diff page colors each side from its whole file, and stays plain past the response bound.
  - The Go session client adds `Client.HighlightCode` and the `highlight` read flags. Related commits: `07f6e29e`, `bfe46789`, `4997128a` (ADR), `aa79a2ba` (contract), `f00cef60` (UTF-16 line mapping), `dc9d0b8d` (Go client).
- `0c01c3d4` — feat(server): list sessions in attention order on request
  - `GET /v1/sessions?order=attention` lists sessions waiting on their user first (longest-waiting first), then running ones, then the rest, most recently updated first. Each session that is not idle carries its activity. Without `order`, the list is unchanged byte for byte; an unknown order is a 400.
  - The Go session client adds `Client.ListSessionsByAttention`, which returns an `UnsupportedError` from a server that ignores the order. Related commits: `e6e4c148` ([ADR 0061](https://github.com/akonwi/kit/blob/main/docs/adrs/0061-order-the-sessions-list-by-attention.md)), `8061fa0f` (contract), `ede4c24e` (Go client).
- `863d0f71` — fix(server): report session errors in the declared error envelope
  - Session failures the server had answered with a bare `{"error": "…"}` body, such as a busy session, a session that can't be deleted while work is active, an image prompt to a text-only model, a missing turn, and an unavailable transcript cursor, now use the documented error body ([ADR 0034](https://github.com/akonwi/kit/blob/main/docs/adrs/0034-use-one-error-body-for-the-session-api.md)) with the generic code for their unchanged status. The terminal client and `kit print` show the reason instead of "daemon returned malformed operation error". Statuses are unchanged; internal errors stay generic.
  - A workspace that changes during a directory listing or file read reports the current workspace in its `stale_workspace` details, as the operations declare.
- `453f1643` — fix(api): project generic and detailed workspace failures
  - The Go session client reports a workspace operation's generic failures (such as `conflict` or `internal`) and its limit and capacity failures as server errors with their details, not "daemon returned malformed workspace error".
- `ff3dd4b9` — fix(api): declare the conflicts and unavailability workspace and attachment operations return
  - The contract now declares the 409 workspace and attachment operations return while a session is being deleted, and the 503 attachment operations return while the server shuts its sessions down. The server already sent these statuses. `59db007d` regenerates the Swift and browser types.
- `d587750b` — chore(highlight): pin tree-sitter-ard a3fd3a3
  - Ard source in the terminal client and in the server's highlighting colors the `.*` dereference (including chains such as `next.*.name`), `&T` and `&mut T` types and `&x`/`&mut x` expressions, struct literal field shorthand (`Config{name}`), and struct tags (`#go:yaml("…")`). The `.@` spelling is no longer recognized, matching Ard v0.46.
- `81993e82` — chore(cli): bump to ard v0.45.0 and cooper 5e31c79 ([#283](https://github.com/akonwi/kit/pull/283)), and `2f13b56d` — fix(cli): replace remaining .@ dereferences with .* ([#284](https://github.com/akonwi/kit/pull/284))

The source tree's native iOS client (`apps/ios`) also gained features in this period, and the shared Swift package and macOS app changed. They aren't part of this release.

## Compatibility and limitations

The session protocol stays 50. Attention ordering, highlighting, and the `highlight` read flags are additive; the newly declared 409 and 503 responses were already sent. Kit 0.57.0 clients and servers work with Kit 0.51.0 and newer clients and servers, and with Kit for macOS 0.8.0 and newer. No upgrade steps are needed beyond the usual `kit update` (or `brew upgrade akonwi/tap/kit`) and a server restart; this release adds no database migration.

The browser client, highlighting, and attention ordering need a 0.57.0 server. Older servers don't serve the browser client, answer `POST /v1/highlight` with a 404, and ignore `order=attention`, returning the usual list. They reject a file or diff read that sets the new `highlight` flag as an invalid request, so a client using the flag must know its server is 0.57.0 or newer; the browser client always talks to the server that served it, and the terminal client and Kit for macOS don't send the flag. The clearer error messages also need a 0.57.0 server; a 0.57.0 terminal client attached to an older server still reports those failures as malformed. The browser client does not show the scratchpad or subagents, and does not work offline. The terminal client and Kit for macOS keep their own highlighters and don't use the attention order.

Known issues: dismissing a subagent just as it finishes can leave its stored conversation until the server restarts ([#258](https://github.com/akonwi/kit/issues/258)). `kit update` treats `/dev/null` as a terminal and exits 0 instead of 2 ([#272](https://github.com/akonwi/kit/issues/272)). If one `kit update` has been downloading for over an hour, another `kit update` run in the same directory can remove its staged download ([#226](https://github.com/akonwi/kit/issues/226)). The terminal client can still panic while opening a session, in the background syntax highlighter ([#210](https://github.com/akonwi/kit/issues/210)). Subagent live streams still drop single events over 16 KiB until the subagent's transcript reloads ([#209](https://github.com/akonwi/kit/issues/209)), and one invalid event still fails every page of a subagent's live stream that holds it ([#208](https://github.com/akonwi/kit/issues/208)). Turn-end events still carry a generic failure reason for failures other than compaction ([#240](https://github.com/akonwi/kit/issues/240)). `kit server pair` lists the addresses from the server's settings rather than the ones it serves ([#222](https://github.com/akonwi/kit/issues/222)).

macOS CLI archives require macOS 14 or newer. Linux archives are built on Ubuntu 24.04 with a glibc 2.39 baseline and are not fully static. Windows and npm distribution are unsupported.
