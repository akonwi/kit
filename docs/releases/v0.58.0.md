# Kit 0.58.0

Kit can now be the agent in Zed and other editors that speak the Agent Client Protocol: the editor runs `kit acp`, and its threads are ordinary Kit sessions on this machine's server. The browser client edits the session scratchpad, shows subagents and their conversations, and lists the third-party software it includes. The terminal client checks for updates every 2 hours instead of every 6. The session protocol stays 50, so this release works with Kit 0.51.0 and newer clients and servers and with Kit for macOS 0.8.0 and newer; restart the server to get the new browser client. The native macOS app is released separately and is not included in CLI archives.

## Use Kit from Zed

Add Kit as a custom agent in Zed's `settings.json`, using the path `which kit` prints:

```json
{
  "agent_servers": {
    "Kit": {
      "type": "custom",
      "command": "/opt/homebrew/bin/kit",
      "args": ["acp"]
    }
  }
}
```

Then pick **Kit** in the Agent Panel's agent selector. Other ACP clients are configured the same way: run `kit acp` as the agent command, or `kit acp --temp` for temporary sessions that are discarded when closed or when `kit acp` exits. To use a Kit home other than `~/.kit`, set `KIT_HOME` in the agent's `env`. Provider logins belong to the Kit server: if none is logged in, run `kit` and use `/login`, or `kit auth login <provider>`, before starting a thread. See [Agent Client Protocol](https://github.com/akonwi/kit/blob/main/docs/features/acp.md).

## What's changed

- `83026e14` — feat(cli): add `kit acp`, an Agent Client Protocol agent for editors ([ADR 0063](https://github.com/akonwi/kit/blob/main/docs/adrs/0063-serve-the-agent-client-protocol-from-kit-acp.md), [#127](https://github.com/akonwi/kit/issues/127))
  - `kit acp` serves ACP v1 on stdin and stdout. Stdout carries only protocol messages; logs and diagnostics go to stderr. It connects to this home's local server and starts it when it isn't running.
  - Editor threads are Kit sessions: a thread started in the editor shows up in the TUI and the macOS app, and the editor's thread list shows the server's persisted sessions, replaying a session's transcript when opened. Kit's tools, plugins, skills, prompt commands, and models are available.
  - Messages and thinking stream as the model writes them; tool calls show their status, the files they touch, and their output, and edits and writes show their change as a diff. The model and thinking level are session config options. Prompt commands and `/compact` are slash commands.
  - A turn another client runs on an open session shows in the editor too; a prompt sent from the editor while it runs is refused. Confirmations become the editor's permission prompts, and text questions, choices, and forms become its forms when it supports them; a question the editor can't show waits for another Kit client to answer. Images and embedded files are attached to the prompt, and linked files are passed as paths.
- `e06b1dc9` — feat(web): edit the session scratchpad
  - **Scratchpad**, in the session menu, edits the Markdown notes a session shares with its forks and the agent. It saves a moment after typing stops and when the page goes away, and keeps an unsaved draft on the device until the server has it. If the shared copy changes under unsaved edits, the draft stays, and **Review changes** lets you keep editing, take the shared copy, or replace it with yours.
- `41bb5486` — feat(web): show subagents and their conversations
  - When the agent starts subagents, a strip under the session's title lists Main and each subagent with its status. Tap one, or the agent's name on a **Start agent** call, to follow its conversation live. A subagent's view has no composer; its menu changes its thinking level, its model once its work finishes, and dismisses it.
- `e8adc8b1` — feat(web): ship third-party notices with the browser client
  - A **Licenses** link on the pairing page lists the packages, fonts, and icons the browser client includes, with their licenses. The build fails on a bundled package without a license file or under a license outside the allowed list.
- `ef4fcc24` — chore: check for updates every 2 hours
  - The terminal client checks for a newer release when it starts and every 2 hours while it stays open, instead of every 6.

The source tree's macOS app and native iOS client also changed in this period. They aren't part of this release.

## Compatibility and limitations

The session protocol stays 50, and this release changes neither the session API nor the server. Kit 0.58.0 clients and servers work with Kit 0.51.0 and newer clients and servers, and with Kit for macOS 0.8.0 and newer. No upgrade steps are needed beyond the usual `kit update` (or `brew upgrade akonwi/tap/kit`); restart the server to get the browser client's scratchpad, subagents, and notices, since the server serves the browser client it was built with. This release adds no database migration.

`kit acp` is a client of the local server like the terminal client, so it can use any protocol-50 server already running in its Kit home. Its limits: **MCP servers configured in the editor are not used**, only those configured in Kit; when an editor passes MCP servers, `kit acp` names the ignored servers on stderr and, when the editor supports notices, in a notice. It connects only to this machine's server, not to servers saved with `kit servers add`. Threads can't be deleted from the editor. Kit doesn't use the editor's terminals or unsaved buffers: commands run in Kit's tool environment and edits go to files on disk. An MCP server's authorization request waits for another Kit client, such as the TUI, to answer.

Known issues: dismissing a subagent just as it finishes can leave its stored conversation until the server restarts ([#258](https://github.com/akonwi/kit/issues/258)). `kit update` treats `/dev/null` as a terminal and exits 0 instead of 2 ([#272](https://github.com/akonwi/kit/issues/272)). If one `kit update` has been downloading for over an hour, another `kit update` run in the same directory can remove its staged download ([#226](https://github.com/akonwi/kit/issues/226)). The terminal client can still panic while opening a session, in the background syntax highlighter ([#210](https://github.com/akonwi/kit/issues/210)). Subagent live streams still drop single events over 16 KiB until the subagent's transcript reloads ([#209](https://github.com/akonwi/kit/issues/209)), and one invalid event still fails every page of a subagent's live stream that holds it ([#208](https://github.com/akonwi/kit/issues/208)). Turn-end events still carry a generic failure reason for failures other than compaction ([#240](https://github.com/akonwi/kit/issues/240)). Working-tree line comments go stale when any other file changes ([#286](https://github.com/akonwi/kit/issues/286)). `kit server pair` lists the addresses from the server's settings rather than the ones it serves ([#222](https://github.com/akonwi/kit/issues/222)). The browser client does not work offline.

macOS CLI archives require macOS 14 or newer. Linux archives are built on Ubuntu 24.04 with a glibc 2.39 baseline and are not fully static. Windows and npm distribution are unsupported.
