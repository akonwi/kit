# Kit 0.59.0

Kit's plugin protocol now has a stable version 2, and a TypeScript helper for writing plugins against it. Plugins opt in with `"protocolVersion": 2` in `plugin.json`. Plugins that don't still speak version 1, which loads and runs unchanged; a session that loads one shows a warning naming it, with a link to the migration guide. Version 1 will be removed in a later release. The session protocol stays 50, so this release works with Kit 0.51.0 and newer clients and servers and with Kit for macOS 0.8.0 and newer; restart the server to use version 2 plugins, since the server runs them. The native macOS app is released separately and is not included in CLI archives.

## For plugin authors

**Nothing breaks in this release.** Every plugin that works with Kit 0.58.0 loads and runs the same way in 0.59.0. What changes is that a session loading a version 1 plugin (one whose `plugin.json` has no `"protocolVersion": 2`) shows one warning, such as:

> my-plugin uses plugin protocol version 1, which a later Kit release removes. Migrate to version 2: https://github.com/akonwi/kit/blob/main/docs/plugin-protocol/migrating-from-v1.md

Version 1 is planned to be removed in a later release, so migrate each plugin before then. The [migration guide](https://github.com/akonwi/kit/blob/main/docs/plugin-protocol/migrating-from-v1.md) has the details; for most plugins it comes down to:

1. In `plugin.json`, add `"protocolVersion": 2`, and point `$schema` at `https://raw.githubusercontent.com/akonwi/kit/main/docs/plugin-protocol/v2/manifest.schema.json`.
2. Answer `initialize` with `{ "protocolVersion": 2 }`.
3. Ignore members and notifications you don't know in what Kit sends. In version 2, Kit rejects request params with members it doesn't know.
4. Stop using what version 2 removes, if the plugin uses any of it: JSON-RPC batches, the header (`kit/header/*`), footer `side`, `clickable` and `action` and `kit/footer/click`, `kit/system-prompt/set` and `clear`, `filterable` on `kit/ui/select`, and `sessionId` on `kit/session/submit-message`. The guide gives each one's replacement.

**A migrated plugin needs Kit 0.59.0 or newer.** Kit 0.58.0 and older refuse a manifest that has `protocolVersion`, so don't migrate a plugin that must still run on an older Kit.

Version 2 also adds `parentId` on dialogs, so Kit closes a dialog when the request it belongs to ends, and `data.reason` on busy and unavailable errors. The [version 2 specification](https://github.com/akonwi/kit/blob/main/docs/plugin-protocol/v2.md) is normative, with JSON Schemas for the manifest and every message in [`docs/plugin-protocol/v2/`](https://github.com/akonwi/kit/tree/main/docs/plugin-protocol/v2), and [`docs/plugin-development.md`](https://github.com/akonwi/kit/blob/main/docs/plugin-development.md) is a checklist for writing one.

### The TypeScript helper

[`sdk/plugin/kit-plugin.ts`](https://github.com/akonwi/kit/blob/v0.59.0/sdk/plugin/kit-plugin.ts) is one dependency-free file that speaks version 2 for a plugin, under Bun or Node 22.6 or newer with type stripping. Nothing is published to a package registry: copy it, and `kit-plugin-testing.ts` for tests, from the Kit repository at the tag of the Kit you run, here `v0.59.0`. A copy's exported `KIT_RELEASE` says which release it came from (`"0.59.0"`). See [`sdk/plugin/README.md`](https://github.com/akonwi/kit/blob/v0.59.0/sdk/plugin/README.md) for an example plugin and manifest.

```ts
import { runPlugin, t, type Kit } from "./kit-plugin.ts";

export async function setup(kit: Kit) {
  await kit.tools.register({
    id: "word_count",
    description: "Count the words in a text",
    input: t.object({ text: t.string() }),
    execute: (input) => `${input.text.split(/\s+/).filter(Boolean).length} words`,
  });
}

if (import.meta.main) runPlugin(setup);
```

`startTestPlugin` from `kit-plugin-testing.ts` runs a plugin's setup against an in-memory Kit that checks identifiers, text, tool schemas, footer targets, URLs, and idempotency keys, but not Kit's byte and count limits, so still try the plugin in Kit.

The built-in kit-customization skill tells the agent how to build version 2 plugins with the helper, and to offer to migrate version 1 plugins it comes across, migrating only if you agree.

## What's changed

- `fa2c4656` — feat(plugins): stabilize the plugin protocol as version 2 ([ADR 0065](https://github.com/akonwi/kit/blob/main/docs/adrs/0065-stabilize-the-plugin-protocol-as-version-2.md))
  - Plugins still use JSON-RPC over stdio. A manifest opts in with `"protocolVersion": 2`; a manifest without it speaks version 1, which is unchanged on the wire.
  - For version 2, Kit rejects batches and request members it doesn't know, reports why a request is busy in `data.reason`, and cancels a dialog when the request named by its `parentId` ends.
  - `api/pluginprotocol` defines version 2's records, methods, and errors, and generates the JSON Schemas in `docs/plugin-protocol/v2/` and the helper's protocol types.
  - The TypeScript helper `sdk/plugin/kit-plugin.ts` and its test harness `sdk/plugin/kit-plugin-testing.ts`.
- `919c809d` — docs(plugins): guide migrating plugins from protocol version 1
  - [`docs/plugin-protocol/migrating-from-v1.md`](https://github.com/akonwi/kit/blob/main/docs/plugin-protocol/migrating-from-v1.md). The kit-customization skill offers to migrate version 1 plugins.
- `987a52f3` — feat(plugins): warn about plugins that speak protocol version 1
  - A session that loads version 1 plugins shows one warning naming them (up to five, then a count of the rest), with a link to the migration guide. The warning goes away when the session leaves the directory of a project plugin that caused it.
- `27d71dd2` — feat(plugins): name the Kit release in the TypeScript helper
  - `kit-plugin.ts` exports `KIT_RELEASE`, the release a copy came from.

The source tree's macOS app also changed in this period. It isn't part of this release.

## Compatibility and limitations

The session protocol stays 50, and the session API is unchanged. Kit 0.59.0 clients and servers work with Kit 0.51.0 and newer clients and servers, and with Kit for macOS 0.8.0 and newer. No upgrade steps are needed beyond the usual `kit update` (or `brew upgrade akonwi/tap/kit`). Plugins run in the server, so restart it to load version 2 plugins and to see the version 1 warning. This release adds no database migration.

Plugin protocol version 1 still works in this release and is planned to be removed in a later one. Plugins that declare `"protocolVersion": 2` need Kit 0.59.0 or newer. The TypeScript helper needs Bun, or Node 22.6 or newer with type stripping, wherever the plugin runs; Kit itself doesn't need either.

Known issues: plugin command failures don't say why ([#241](https://github.com/akonwi/kit/issues/241)). Dismissing a subagent just as it finishes can leave its stored conversation until the server restarts ([#258](https://github.com/akonwi/kit/issues/258)). `kit update` treats `/dev/null` as a terminal and exits 0 instead of 2 ([#272](https://github.com/akonwi/kit/issues/272)). If one `kit update` has been downloading for over an hour, another `kit update` run in the same directory can remove its staged download ([#226](https://github.com/akonwi/kit/issues/226)). The terminal client can still panic while opening a session, in the background syntax highlighter ([#210](https://github.com/akonwi/kit/issues/210)). Subagent live streams still drop single events over 16 KiB until the subagent's transcript reloads ([#209](https://github.com/akonwi/kit/issues/209)), and one invalid event still fails every page of a subagent's live stream that holds it ([#208](https://github.com/akonwi/kit/issues/208)). Turn-end events still carry a generic failure reason for failures other than compaction ([#240](https://github.com/akonwi/kit/issues/240)). Working-tree line comments go stale when any other file changes ([#286](https://github.com/akonwi/kit/issues/286)). `kit server pair` lists the addresses from the server's settings rather than the ones it serves ([#222](https://github.com/akonwi/kit/issues/222)). The browser client does not work offline.

macOS CLI archives require macOS 14 or newer. Linux archives are built on Ubuntu 24.04 with a glibc 2.39 baseline and are not fully static. Windows and npm distribution are unsupported.
