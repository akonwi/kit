# Kit 0.62.0

File tabs can now be searched: Ctrl+F in the terminal client and ⌘F (Ctrl+F off Apple devices) in the browser client open a find bar, and every client matches the same way. In Rex, opening a view whose pane is already open now shows the new line or annotation in that pane without restarting it. Shell commands see their session's ID in `KIT_SESSION_ID`, and sessions get a built-in `rex` skill when the server's machine has Rex. Working-tree line comments no longer go stale when other files change. The session protocol stays 50, so this release works with Kit 0.51.0 and newer clients and servers and with Kit for macOS 0.8.0 and newer. The native macOS app is released separately and is not included in CLI archives.

## Find in a file

- **Terminal:** Ctrl+F on a File tab, or **find** in the command palette, opens a row under the tab's header. Return or ↓ go to the next match and Shift-Return or ↑ to the previous one, wrapping at either end; Alt+C and Alt+W toggle **Match Case** and **Whole Word**; Esc closes the row and gives the keyboard back to the composer. A code file is searched as shown; a rendered Markdown file's paragraphs, headings, lists, quotes, callouts, tables, and code blocks are searched, but not diagrams, data figures, or diff fences. The current match becomes the cursor line in source, scrolling sideways if needed, or marks its block's gutter in a rendered Markdown file. On a File tab, Ctrl+F no longer moves the composer's cursor right. In a macOS terminal, the Alt shortcuts need Option set to act as Meta.
- **Browser:** the magnifier in a file's header, or ⌘F, opens a find bar under the header. Return and ⌘G step through matches, ⌘E searches for the selected text, and Esc closes the bar. A browser without the CSS Custom Highlight API counts and scrolls to matches without tinting them.

Find matches the query as written, not as a regular expression, and ignores case unless Match Case is on. The rules and the cases every client is tested against are in `testdata/find`; the server's reference matcher is `internal/textfind`. See [find in a file](https://github.com/akonwi/kit/blob/v0.62.0/docs/features/find-in-file.md).

## File links open at their lines

In the browser client, a transcript link to a file in the session's folder opens the file viewer at the lines its `path#L42` or `path#L42-L50` target names, and a Markdown file's relative links resolve from its folder. The system prompt now asks the model to put a linked file's lines in the link target, GitHub's way (`[src/server.go:42](src/server.go#L42)`); the terminal client shows the link's label either way. See [file links](https://github.com/akonwi/kit/blob/v0.62.0/docs/features/file-links.md).

## Rex panes

Opening a view at a line or an annotation when its Rex pane is already open now asks the running view to show it and focuses the pane; the view keeps its own state, such as its Diff target or Markdown preview. This uses two additive session routes, `POST /v1/sessions/{id}/views/{viewID}/reveal` and `GET /v1/sessions/{id}/views/{viewID}/events`, which the Go client exposes as `Session.RevealView` and `Session.WatchViewReveals` ([ADR 0068](https://github.com/akonwi/kit/blob/main/docs/adrs/0068-reveal-targets-in-open-workspace-views.md)). With a server that predates them, the pane restarts in place as before, so restart the server on 0.62.0 to get the new behavior.

In Rex, **Settings › This terminal** has an "Open views in Rex panes" toggle for the `workspacePanes` setting. It applies to the next view opened. Outside Rex, and in tmux inside Rex, the row isn't shown.

## Session ID and the Rex skill

Commands from the bash tool and the composer's `!` commands see their session's ID in `KIT_SESSION_ID`, so a background job can call back with `kit print --session "$KIT_SESSION_ID"`. When the server's machine has the `rex` command, sessions get a built-in `rex` skill that points the model at `rex skill show` and covers what differs under Kit; a user or project skill named `rex` replaces it. See [calling back into a session](https://github.com/akonwi/kit/blob/v0.62.0/docs/features/print-mode.md#calling-back-into-a-session) and [the Rex skill](https://github.com/akonwi/kit/blob/v0.62.0/docs/features/skills.md#the-rex-skill).

## Compatibility and limitations

The session protocol stays 50. The two view routes are additive, and the OpenAPI compatibility check against 0.61.0 reports no findings. Kit 0.62.0 clients and servers work with Kit 0.51.0 and newer clients and servers, and with Kit for macOS 0.8.0 and newer. No upgrade steps are needed beyond the usual `kit update` (or `brew upgrade akonwi/tap/kit`), then restarting the server for `KIT_SESSION_ID`, the Rex skill, the file-link prompt, the working-tree comment fix, and pane reveals to take effect. This release adds no database migration and doesn't change the plugin protocol.

The speech example plugin now registers its toggle on every platform; off macOS the command shows a "Speech needs macOS" warning and never enables speech.

Rex is in preview, and pane placement was checked against Rex 0.1.0-preview.14 (API revision 12).

Known issues: plugin command failures don't say why ([#241](https://github.com/akonwi/kit/issues/241)). Dismissing a subagent just as it finishes can leave its stored conversation until the server restarts ([#258](https://github.com/akonwi/kit/issues/258)). `kit update` treats `/dev/null` as a terminal and exits 0 instead of 2 ([#272](https://github.com/akonwi/kit/issues/272)). If one `kit update` has been downloading for over an hour, another `kit update` run in the same directory can remove its staged download ([#226](https://github.com/akonwi/kit/issues/226)). The terminal client can still panic while opening a session, in the background syntax highlighter ([#210](https://github.com/akonwi/kit/issues/210)). Subagent live streams still drop single events over 16 KiB until the subagent's transcript reloads ([#209](https://github.com/akonwi/kit/issues/209)), and one invalid event still fails every page of a subagent's live stream that holds it ([#208](https://github.com/akonwi/kit/issues/208)). Turn-end events still carry a generic failure reason for failures other than compaction ([#240](https://github.com/akonwi/kit/issues/240)). Diff file summaries never carry line counts ([#285](https://github.com/akonwi/kit/issues/285)). `kit server pair` lists the addresses from the server's settings rather than the ones it serves ([#222](https://github.com/akonwi/kit/issues/222)). The browser client does not work offline.

macOS CLI archives require macOS 14 or newer. Linux archives are built on Ubuntu 24.04 with a glibc 2.39 baseline and are not fully static. Windows and npm distribution are unsupported.
