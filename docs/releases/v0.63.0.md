# Kit 0.63.0

You can now comment on part of a Mermaid diagram in the terminal and browser clients: turn on **Annotate**, pick a node, edge, subgraph, participant, message, note, or block, and write a comment that's sent with your next message. Changes now compares a branch against the latest fetched version of its base, so a stale local `main` no longer attributes commits already on `origin/main` to your branch. The session protocol stays 50, so this release works with Kit 0.51.0 and newer clients and servers and with Kit for macOS 0.8.0 and newer. The native macOS app is released separately and is not included in CLI archives.

## Comment on part of a diagram

- **Terminal:** a drawn diagram in a reply has an **Annotate** toggle under it. While it's on, the drawing takes the mouse instead of selecting text: the part under the pointer is tinted, parts with a waiting comment are in the accent color, and a click on a part opens a comment box. Enter saves and Esc cancels.
- **Browser:** a Mermaid card and its full-screen viewer have **Annotate**. With it on, the pointer outlines the part under it, a click picks it, and a comment box under the drawing adds the comment to the composer. Thin lines take the pointer in a wider band while the mode is on.

Saved comments wait as chips above the composer until you send your next message, and × removes one. A message holds up to 16. Each is added after your text as a fenced block tagged with a random nonce, with what Kit read from the diagram about the part (its edges and neighbours, or what it contains) and the diagram's source. A sent message shows its comments under its text, and composer history recalls only the text. Prompt commands don't take comments, and comments stay in the client you wrote them in until they're sent.

Only blocks numbered from 1, a blank line apart, that run to the end of a message are read as its comments; annotation-shaped text elsewhere in a message stays part of the message. The terminal's renderer is the reference: the shared fixtures in `testdata/mermaid` now record where each part is drawn (`.regions`) and the text the model gets for comments on it (`annotations/`), and the browser's TypeScript port is held to them. See [commenting on part of a diagram](https://github.com/akonwi/kit/blob/v0.63.0/docs/features/mermaid.md#commenting-on-part-of-a-diagram).

## Changes compares against the latest fetched base

A branch target in Changes used to diff from the merge base with the local base branch. Each base now also considers its fetched remote-tracking counterpart (the branch's configured upstream, otherwise the same name on the default remote) and uses whichever gives the closer merge base. A base that exists only on the default remote, such as `origin/main` in a clone without a local `main`, is offered as the default. The target's label names the ref used, for example `feature vs origin/main`. Listing targets never fetches; it uses only refs already fetched. See [ADR 0024](https://github.com/akonwi/kit/blob/v0.63.0/docs/adrs/0024-generalize-diff-review-targets.md#branch-bases).

## Compatibility and limitations

The session protocol stays 50 and the OpenAPI contract is unchanged; the OpenAPI compatibility check against 0.62.0 reports no findings. Kit 0.63.0 clients and servers work with Kit 0.51.0 and newer clients and servers, and with Kit for macOS 0.8.0 and newer. No upgrade steps are needed beyond the usual `kit update` (or `brew upgrade akonwi/tap/kit`). Diagram comments are a client feature and work against any compatible server; restart the server on 0.63.0 for the Changes base fix. This release adds no database migration and doesn't change the plugin protocol.

Diagram comments are sent as text in the message, so a client that predates them (terminal or browser before 0.63.0, or Kit for macOS before 0.19.0) shows a commented message's blocks as part of its text. In the terminal, annotating needs mouse reporting; there is no keyboard way to pick a part. Only flowcharts and sequence diagrams that Kit draws can be annotated.

Known issues: plugin command failures don't say why ([#241](https://github.com/akonwi/kit/issues/241)). Dismissing a subagent just as it finishes can leave its stored conversation until the server restarts ([#258](https://github.com/akonwi/kit/issues/258)). `kit update` treats `/dev/null` as a terminal and exits 0 instead of 2 ([#272](https://github.com/akonwi/kit/issues/272)). If one `kit update` has been downloading for over an hour, another `kit update` run in the same directory can remove its staged download ([#226](https://github.com/akonwi/kit/issues/226)). The terminal client can still panic while opening a session, in the background syntax highlighter ([#210](https://github.com/akonwi/kit/issues/210)). Subagent live streams still drop single events over 16 KiB until the subagent's transcript reloads ([#209](https://github.com/akonwi/kit/issues/209)), and one invalid event still fails every page of a subagent's live stream that holds it ([#208](https://github.com/akonwi/kit/issues/208)). Turn-end events still carry a generic failure reason for failures other than compaction ([#240](https://github.com/akonwi/kit/issues/240)). Diff file summaries never carry line counts ([#285](https://github.com/akonwi/kit/issues/285)). `kit server pair` lists the addresses from the server's settings rather than the ones it serves ([#222](https://github.com/akonwi/kit/issues/222)). The browser client does not work offline.

macOS CLI archives require macOS 14 or newer. Linux archives are built on Ubuntu 24.04 with a glibc 2.39 baseline and are not fully static. Windows and npm distribution are unsupported.
