# Kit 0.64.0

**This release removes plugin protocol version 1.** A plugin whose `plugin.json` doesn't declare `"protocolVersion": 2` no longer loads: Kit doesn't start it, and the session shows a warning naming it with a link to the migration guide. Version 1 has been deprecated since 0.59.0, and the 0.62.0 and 0.63.0 releases still ran it with that warning. Migrate any version 1 plugins before you upgrade; see the [Upgrade guide](#upgrade-guide). Plugins that already speak version 2 are unaffected.

Stack figures with more than four segments in a row are now drawn instead of failing: the three largest are kept and the rest are added into `other`. The session protocol stays 50, so this release works with Kit 0.51.0 and newer clients and servers and with Kit for macOS 0.8.0 and newer. The native macOS app is released separately and is not included in CLI archives.

## Plugin protocol version 1 is removed

Kit now runs only plugins whose manifest declares `"protocolVersion": 2` ([ADR 0065](https://github.com/akonwi/kit/blob/v0.64.0/docs/adrs/0065-stabilize-the-plugin-protocol-as-version-2.md), [specification](https://github.com/akonwi/kit/blob/v0.64.0/docs/plugin-protocol/v2.md)). A manifest without it is rejected when the session discovers its plugins, before anything is started. The session's warning names up to five such plugins, then a count of the rest, for example:

> my-plugin uses plugin protocol version 1, which Kit no longer runs. Migrate to version 2: https://github.com/akonwi/kit/blob/main/docs/plugin-protocol/migrating-from-v1.md

The host no longer implements what only version 1 had: its `initialize` exchange, JSON-RPC batches (an array is always answered with `-32600`), busy errors without a reason, header items, clickable or left-side footer items, `kit/system-prompt/set`, and `filterable` on `kit/ui/select`. The version 1 specification, the profile of how Kit ran version 1 plugins, and the version 1 JSON schemas are no longer in the repository; the [version 2 schemas](https://github.com/akonwi/kit/tree/v0.64.0/docs/plugin-protocol/v2) are the only ones. The built-in kit-customization skill now tells the agent that Kit no longer runs version 1 plugins, and still offers to migrate one only if you agree.

## Stack figures fold extra segments into other

A `stack` figure row may now have more than four segments. Kit keeps the three whose values, summed across all rows, are largest, in the order written (the earlier on a tie), and adds the rest into a fourth segment, so every row keeps the same segments and its total is unchanged. A segment already named `other` is always added into the fold. The legend names the fold `other (…)` with the folded names, as many whole names as fit in 32 characters and then `…`, for example `other (dyld, window, server, …)`. The terminal and browser clients draw it the same way, held to shared fixtures.

A row with only one segment still isn't drawn, nor are rows with more than four segments whose names or order differ; both now say to use a `bars` figure instead. The built-in kit-figures skill now steers one total broken into many parts (startup time by phase, a bundle by file) to `bars` with `percent="total"`, and keeps `stack` for comparing two to four parts across rows. See [figures](https://github.com/akonwi/kit/blob/v0.64.0/docs/figures.md).

## Upgrade guide

**Who is affected:** anyone with a plugin whose `plugin.json` lacks `"protocolVersion": 2`, in the Kit home's `plugins/` directory (`~/.kit/plugins/` by default) or a project's `.kit/plugins/`. If you saw the "uses plugin protocol version 1" warning in Kit 0.59.0 through 0.63.0, you are affected. To list candidates:

```sh
grep -LE '"protocolVersion"[[:space:]]*:[[:space:]]*2' ~/.kit/plugins/*/plugin.json .kit/plugins/*/plugin.json 2>/dev/null
```

**Order:** migrate first, then upgrade. A plugin that declares version 2 runs on Kit 0.59.0 and newer, so you can migrate and test it on your current Kit before installing 0.64.0. Plugins are run by the server, so the removal takes effect once the server runs 0.64.0; until you restart it, an older server keeps loading version 1 plugins. If a plugin can't be migrated yet, stay on 0.63.0.

**Migrating a plugin to version 2** (full details in the [migration guide](https://github.com/akonwi/kit/blob/v0.64.0/docs/plugin-protocol/migrating-from-v1.md) and the [version 2 specification](https://github.com/akonwi/kit/blob/v0.64.0/docs/plugin-protocol/v2.md)):

1. In `plugin.json`, add `"protocolVersion": 2`, and point `$schema` at `https://raw.githubusercontent.com/akonwi/kit/v0.64.0/docs/plugin-protocol/v2/manifest.schema.json`.
2. Answer `initialize` with `{ "protocolVersion": 2 }`. Its params also carry `kit.version` and `instance.id`; ignore them if you don't need them.
3. Ignore members and notifications you don't recognize in what Kit sends. Kit rejects request params with unknown members with `-32602`.
4. Replace anything version 2 removed:

   | Version 1 | In version 2 |
   | --- | --- |
   | Batches (JSON arrays) | One message per line. |
   | `kit/header/*` and `kit/header/click` | A footer item. |
   | `side`, `clickable`, `action` on `kit/footer/set`; `kit/footer/click` | Omit them; offer the click's behaviour as a command. |
   | `kit/system-prompt/set` and `clear` | No replacement; move standing instructions to a context file or skill. |
   | `filterable` on `kit/ui/select` | Omit it. |
   | `sessionId` on `kit/session/submit-message` | Omit it; the result is `{ messageId, turnId }`. |
   | Handling of error `-32004` | Drop it; Kit never sends it. |

5. Optionally adopt what version 2 adds: `parentId` on dialogs opened while serving a Kit request (Kit cancels them when the request ends), and `data.reason` on `-32006` (`busy`, `session_busy`, `rate_limited`) and `-32000` (`interactivity_unavailable`).
6. Check it: validate each line the plugin writes against [`v2/protocol.schema.json`](https://github.com/akonwi/kit/blob/v0.64.0/docs/plugin-protocol/v2/protocol.schema.json), then reload a session (the command palette's `reload`) and confirm the plugin starts without a failure notification.

**TypeScript plugins** can instead use Kit's helper, which speaks version 2 for you. Copy [`sdk/plugin/kit-plugin.ts`](https://raw.githubusercontent.com/akonwi/kit/v0.64.0/sdk/plugin/kit-plugin.ts), and [`sdk/plugin/kit-plugin-testing.ts`](https://raw.githubusercontent.com/akonwi/kit/v0.64.0/sdk/plugin/kit-plugin-testing.ts) for tests, from the `v0.64.0` tag; their `KIT_RELEASE` is `"0.64.0"`. No package is published. Then delete the plugin's own JSON-RPC endpoint and `initialize` handling, move each registration to the helper's namespaces (`kit.commands`, `kit.tools`, `kit.footer`, `kit.ui`) with its handler, for example `kit.tools.register({ id, input, execute(input, ctx) })` with the input schema built with `t`, take cancellation from `ctx.signal`, and open request-scoped dialogs with `ctx.ui`. `startTestPlugin` from `kit-plugin-testing.ts` runs the plugin against an in-memory Kit. The helper needs Bun, or Node 22.6 or newer with type stripping, wherever the plugin runs. See the [helper's README](https://github.com/akonwi/kit/blob/v0.64.0/sdk/plugin/README.md).

**With a coding assistant:** ask Kit's agent to migrate the plugin. The built-in kit-customization skill points it at the migration guide and the helper at your running version's tag.

## Compatibility and limitations

The session protocol stays 50 and the OpenAPI contract is unchanged; the OpenAPI compatibility check against 0.63.0 reports no findings. Kit 0.64.0 clients and servers work with Kit 0.51.0 and newer clients and servers, and with Kit for macOS 0.8.0 and newer. Beyond migrating version 1 plugins, no upgrade steps are needed besides the usual `kit update` (or `brew upgrade akonwi/tap/kit`), then restarting the server on 0.64.0. This release adds no database migration.

The plugin removal is server-side and the figure folding is client-side. A terminal or browser client older than 0.64.0, or Kit for macOS 0.19.0 or older, still refuses to draw a stack with more than four segments. The session API keeps its `filterable` interaction member for now, though no plugin can set it.

Known issues: plugin command failures don't say why ([#241](https://github.com/akonwi/kit/issues/241)). Dismissing a subagent just as it finishes can leave its stored conversation until the server restarts ([#258](https://github.com/akonwi/kit/issues/258)). `kit update` treats `/dev/null` as a terminal and exits 0 instead of 2 ([#272](https://github.com/akonwi/kit/issues/272)). If one `kit update` has been downloading for over an hour, another `kit update` run in the same directory can remove its staged download ([#226](https://github.com/akonwi/kit/issues/226)). The terminal client can still panic while opening a session, in the background syntax highlighter ([#210](https://github.com/akonwi/kit/issues/210)). Subagent live streams still drop single events over 16 KiB until the subagent's transcript reloads ([#209](https://github.com/akonwi/kit/issues/209)), and one invalid event still fails every page of a subagent's live stream that holds it ([#208](https://github.com/akonwi/kit/issues/208)). Turn-end events still carry a generic failure reason for failures other than compaction ([#240](https://github.com/akonwi/kit/issues/240)). Diff file summaries never carry line counts ([#285](https://github.com/akonwi/kit/issues/285)). `kit server pair` lists the addresses from the server's settings rather than the ones it serves ([#222](https://github.com/akonwi/kit/issues/222)). The browser client does not work offline.

macOS CLI archives require macOS 14 or newer. Linux archives are built on Ubuntu 24.04 with a glibc 2.39 baseline and are not fully static. Windows and npm distribution are unsupported.
