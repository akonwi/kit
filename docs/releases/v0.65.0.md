# Kit 0.65.0

**This release moves the session protocol from 50 to 51.** Upgrade the server and every client together: Kit 0.65.0, Kit for macOS 0.20.0, and the new iOS TestFlight build speak protocol 51, and clients released before them can't attach to a 0.65.0 server. See the [Upgrade guide](#upgrade-guide).

Shell commands are now visible in every client attached to a session, whichever client ran them, including commands kept out of the model's context. You can comment on selected text instead of quoting it. A session can delete its child sessions once you approve. Queued follow-ups survive a server restart. Images that `show_image` stores up to 16 MiB and 24 megapixels are now served, and line-limited file previews are much faster. The native macOS app is released separately and is not included in CLI archives.

## Shell commands in every client

A composer shell command (`!command`, or `!!command` to keep it from the model) now shows in every client attached to the session, not only the one that ran it ([ADR 0072](https://github.com/akonwi/kit/blob/v0.65.0/docs/adrs/0072-share-shell-executions-with-every-attached-client.md), fixes [#130](https://github.com/akonwi/kit/issues/130)). Each client shows it with the same row as its own commands: a spinner while it runs, then its output and outcome, and the not-in-context mark for an excluded command. The running command keeps the session busy in every client, and Stop (Escape in the terminal client) stops it from any of them.

The server announces each command on the live session stream as `bash.started` and `bash.completed`. Snapshots list, in `bashExecutions`, the 32 most recent commands the transcript doesn't record: the running one, excluded ones, and included ones that never joined the conversation, such as one interrupted by a server shutdown. Excluded commands now survive a client reload, and clients no longer poll for their own commands. Output still isn't streamed while a command runs; every client, including the one that ran it, sees the output when it settles. Excluded output still never reaches the model.

From protocol 51, the session event union is open ([ADR 0032](https://github.com/akonwi/kit/blob/v0.65.0/docs/adrs/0032-model-protocol-variants-as-discriminated-unions.md) and [ADR 0033](https://github.com/akonwi/kit/blob/v0.65.0/docs/adrs/0033-adopt-consistent-protocol-event-vocabulary.md) as amended by ADR 0072): clients skip session events of kinds they don't know, advancing their cursor past them, and ignore top-level snapshot members they don't know. Later releases can add event kinds and snapshot members without a protocol bump; changing the fields of an existing kind still needs one.

## Comment on selected text

Select text in a reply, your own message, a tool's or shell command's output, the scratchpad, or a subagent's tab, and choose **Comment** where you used to choose Quote ([ADR 0070](https://github.com/akonwi/kit/blob/v0.65.0/docs/adrs/0070-comment-on-selected-text.md)). The comment waits in the composer as a chip and is sent after your message's text as a numbered `<text-annotation>` block holding your comment, where the words came from (for example `Tool output · go test ./internal/pair`), and the selected words, fenced as untrusted with a per-block nonce. The terminal client and Kit for macOS write comments; the terminal client, the browser client, Kit for macOS, and the iOS app show a sent message's comments under a closed "N comments" row that opens to each one. A message holds at most 16 text comments, and a selection over 4 KiB is cut at a character boundary. In the terminal client and Kit for macOS, message history recalls a message's own text without its comment blocks. All clients read and write the blocks the same way, held to the shared fixtures in `testdata/text-annotations`.

## Delete child sessions

The new `delete_session` model tool lets a top-level persistent session delete its child sessions, those whose parent is that session, with all of their descendants ([ADR 0071](https://github.com/akonwi/kit/blob/v0.65.0/docs/adrs/0071-let-a-session-delete-its-child-sessions.md)). It asks you once, listing every session it would delete, and deletes nothing unless you approve. If any of them is busy it refuses the whole call. If you decline, the model is told so. IDs that don't name one of its children are reported as not deleted, without refusing the rest. `peer_session` with `action: "discover"` and `children: true` lists the session's direct children with their number of descendants. Every client titles a `delete_session` call by how many sessions it names and then shows which were deleted or that you declined.

## Follow-ups survive restarts

Queued follow-ups now wait in the session droid's durable queue ([ADR 0073](https://github.com/akonwi/kit/blob/v0.65.0/docs/adrs/0073-layer-the-session-runtime-into-public-packages.md), stage 1), so a restart of the Kit server no longer loses them. After a restart, a session's queue starts when the server next loads the session, after the session resumes any turn the restart interrupted. The server loads a session the first time anything needs it, not only when you open it: a client fetching it, a peer query from another session, a subagent result arriving, an ACP client, or a plugin reading its state. Any of these can start a restored queue. A follow-up's attachments and annotations are captured when you send it; removing an attachment afterwards no longer keeps the follow-up from starting. Sending the queue at once steers every queued prompt into the running turn in one step and announces the emptied queue with a single `follow_ups.changed`. See [follow-ups](https://github.com/akonwi/kit/blob/v0.65.0/docs/features/follow-ups.md).

Two problems in the new queue were fixed before release: a snapshot taken during a run after a fork could wait forever, and a prompt sent just after a queued follow-up finished could be refused as busy.

## Other changes

- **Larger shown images are served.** `show_image` stores images up to 16 MiB and 24 megapixels, but the server only served images within the model-image limits (10 MiB, 12 megapixels), so a larger one, such as a 2x design export, failed to load in every client. The server now serves them, and the terminal client previews them. Naming such an image as a prompt attachment now fails before the model is called, saying which limit it exceeds. Uploads keep the model-image limits.
- **Faster file previews.** Reading a line-limited preview of a file was quadratic in its length; a preview of a 0.5–4 MB file cut at 5,000 lines took 1–2 s of CPU. It now takes linear time.
- **droids SDK:** applications can queue prompts that start the next turns (`Enqueue`, with listing, withdrawal, promotion to steering, and `StartedPrompts` to follow the turns the queue starts across restarts). Droids can also ask the person durable questions, confirm tools before they run (`RequireConfirmation` or a `Confirm` callback), and give models the standard question tools `ConfirmTool`, `InputTool`, `SelectTool`, and `GuidedTool`; declared questions and the turns waiting on them survive restarts. Kit uses the queue for follow-ups but doesn't use the interactions yet. See the [droids README](https://github.com/akonwi/kit/blob/v0.65.0/droids/README.md).

## Upgrade guide

Kit 0.65.0 moves the session protocol from 50 to 51, because older clients reject the new shell events and snapshot member. Clients and servers connect only when they speak the same protocol, so:

- Kit 0.64.0 and older can't attach to a 0.65.0 server, and a 0.65.0 client refuses a running 0.64.0 or older server. Each side's incompatible-server screen says which side to update. A 0.65.0 client leaves an older server running; it won't replace it on its own.
- Kit for macOS 0.19.1 and older, and iOS TestFlight builds before this release, can't attach to a 0.65.0 server. Kit for macOS 0.20.0 and the new iOS TestFlight build need a 0.65.0 or newer server.
- The browser client is served by the server, so it updates with it. Reload open browser tabs after the restart.

Let active work settle, then upgrade in this order:

1. Upgrade Kit. Run `kit update`, which installs 0.65.0 (with `brew upgrade akonwi/tap/kit` if Kit came from Homebrew) and offers to restart this home's server, saying how many sessions the restart interrupts. Or do it by hand:

   ```sh
   brew update && brew upgrade akonwi/tap/kit
   ```

2. Restart the server, if `kit update` didn't, and check it:

   ```sh
   kit server restart
   kit version
   kit server status
   ```

   Interrupted turns resume and queued follow-ups start when each session next loads.

3. Update Kit for macOS to 0.20.0 (its update sheet, or `brew upgrade --cask akonwi/tap/kit-app`) and install the new iOS TestFlight build. Until you do, they show the incompatible-server screen.

Servers on other machines, reached over SSH, Tailscale, or pairing, are never changed by `kit update` here. Upgrade Kit on each of those machines and restart its server, and update every client that attaches to it at the same time.

This release adds no database migration.

**Plugin authors:** the plugin protocol doesn't change, and existing plugins keep working. Plugins don't receive shell events. The TypeScript helper's `KIT_RELEASE` is `"0.65.0"`.

**Client and Go program authors:** update `github.com/akonwi/kit` to v0.65.0, which speaks protocol 51.

- **New events:** `bash.started` (`BashStartedEvent`) and `bash.completed` (`BashCompletedEvent`), session-scoped with no turn ID, each with `BashExecution`, the command as `Session.Bash` returns it. An included command also appears as a `bash` boundary with the same execution ID; show one row per ID. When `bash.completed` arrives, the session can start the next command.
- **Snapshot member:** `SessionSnapshot.BashExecutions` lists up to `MaxSnapshotBashExecutions` (32) commands the transcript doesn't record, in sequence order with their output. Take commands from these and the events instead of polling `Session.Bash`; use it only to learn whether a start request whose answer was lost started the command.
- **Open union:** an event of a kind your protocol version doesn't declare decodes as `UnrecognizedSessionEvent` with its `Kind`; the client's event stream skips it and advances the cursor. Code that switches over event payloads should ignore it. Snapshots ignore unknown top-level members. Known kinds and members are still decoded strictly.
- **Stored images:** `MaxStoredImageBytes` (16 MiB), `MaxStoredImagePixels` (24,000,000), and `MaxStoredImageSide` (8192) bound images a session stores for display; attachment metadata is validated against them. Model-image limits still bound uploads and prompt attachments.

**`droids` SDK users:** the queue, interactions, and question tools are additions; existing code keeps working.

## Compatibility and limitations

The session protocol is 51. Kit 0.65.0 clients and servers work only with Kit 0.65.0 and newer clients and servers on protocol 51, with Kit for macOS 0.20.0 and newer, and with the iOS TestFlight build released with them. The OpenAPI compatibility check against 0.64.0 reports only the protocol header's move from 50 to 51 and the two new event variants, both acknowledged by protocol 51. From 51 on, new session event kinds and new top-level snapshot members are additive and don't change the protocol.

A Kit 0.64.0 or older terminal client or Go client still rejects shown images over 12 megapixels or 10 MiB; it can't attach to a 0.65.0 server anyway, so update it with the server.

Known issues: plugin command failures don't say why ([#241](https://github.com/akonwi/kit/issues/241)). Dismissing a subagent just as it finishes can leave its stored conversation until the server restarts ([#258](https://github.com/akonwi/kit/issues/258)). `kit update` treats `/dev/null` as a terminal and exits 0 instead of 2 ([#272](https://github.com/akonwi/kit/issues/272)). If one `kit update` has been downloading for over an hour, another `kit update` run in the same directory can remove its staged download ([#226](https://github.com/akonwi/kit/issues/226)). The terminal client can still panic while opening a session, in the background syntax highlighter ([#210](https://github.com/akonwi/kit/issues/210)). Subagent live streams still drop single events over 16 KiB until the subagent's transcript reloads ([#209](https://github.com/akonwi/kit/issues/209)), and one invalid event still fails every page of a subagent's live stream that holds it ([#208](https://github.com/akonwi/kit/issues/208)). Turn-end events still carry a generic failure reason for failures other than compaction ([#240](https://github.com/akonwi/kit/issues/240)). Diff file summaries never carry line counts ([#285](https://github.com/akonwi/kit/issues/285)). `kit server pair` lists the addresses from the server's settings rather than the ones it serves ([#222](https://github.com/akonwi/kit/issues/222)). The browser client does not work offline.

macOS CLI archives require macOS 14 or newer. Linux archives are built on Ubuntu 24.04 with a glibc 2.39 baseline and are not fully static. Windows and npm distribution are unsupported.
