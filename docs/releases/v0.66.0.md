# Kit 0.66.0

Clients now download whole files instead of reading bounded previews, so the terminal client and the browser client show long files in full, up to their own limits. The model's questions, MCP authorizations, plugin dialogs, and `delete_session` approvals now survive a server restart, and you can answer them after it. Comment boxes in the terminal client open at the words they comment on. The session protocol stays at 51, so this release needs no coordinated client upgrade, but Kit for macOS 0.21.0 and later need this server to show files. The native macOS app is released separately and is not included in CLI archives.

## Whole-file downloads

The new `GET` and `HEAD /v1/sessions/{id}/files/content` route serves the complete bytes of a workspace file, or of a host file when the request names no workspace ([ADR 0074](https://github.com/akonwi/kit/blob/v0.66.0/docs/adrs/0074-download-file-content-to-clients.md)). The file's revision is a strong `ETag`, and `If-None-Match` (`304`), `If-Match` (`412`), and one `Range` with `If-Range` (`206`) behave as ordinary HTTP, so a client can revalidate a copy with a bodiless request and resume an interrupted download. A file that reports a size of zero, as some special files do, is served to its end without an `ETag` or ranges. Downloads take one of two slots per session and eight per server, so they can't crowd out previews and listings. The response carries `Content-Disposition: attachment`, `X-Content-Type-Options: nosniff`, and `Content-Security-Policy: sandbox; default-src 'none'`, so a browser that opens a download URL directly won't render or run it with the browser client's origin. The public Go client adds `Session.DownloadFile` and `Session.CheckFile`.

- **Terminal client:** file tabs show workspace and host files from downloads alone. Text shows up to 2 MiB and 65,536 lines, cut at a line end (or at a whole character when the first line doesn't fit), and the footer says how much shows. Host tabs show PNG, JPEG, GIF, and WebP images up to 16 MiB and 24 megapixels; other binary files say they can't be shown. Showing a tab again revalidates its copy. A file that changes while it downloads is downloaded once more and then kept with a note. Lines are split and highlighted off the UI thread.
- **Browser client:** file views download workspace files whole, up to 8 MiB of UTF-8 text, and draw only the lines near the view, in 128-line blocks, so long files stay responsive. Find searches every line. Syntax colors now come from [@pierre/highlights](https://www.npmjs.com/package/@pierre/highlights), a WebAssembly highlighter loaded the first time a file is shown, so the browser client's Content-Security-Policy now allows `'wasm-unsafe-eval'`; it still allows no inline styles. Markdown over 1 MiB opens as source. A copy that changed again while it downloaded keeps no revision and takes no comments. Fixes [#296](https://github.com/akonwi/kit/issues/296).
- **Deprecated reads:** `readWorkspaceFile` and `readHostFile` are marked `deprecated: true` in the OpenAPI document and still work; a later release removes them ([#298](https://github.com/akonwi/kit/issues/298)). Operations can now be marked deprecated in the published contract.

Against a server older than 0.66.0, which doesn't have the route, the terminal client's and the browser client's file tabs, and Kit for macOS 0.21.0's, say the server needs an update. Everything else keeps working.

## Questions and approvals survive restarts

The model's question tools (`confirm_from_user`, `input_from_user`, `select_from_user`, `guided_questions`), MCP authorization, plugin dialogs, and `delete_session` approvals are now asked through the session's droid ([ADR 0073](https://github.com/akonwi/kit/blob/v0.66.0/docs/adrs/0073-make-droids-the-unit-applications-compose-and-share-conversation-ui.md), step 2b). They are durable:

- A question still waiting when the Kit server restarts is waiting again when the session next loads, and answering it continues the turn. If the plugins' before-tool policy changed across the restart, plugin before-hooks run again for the call before it continues.
- Sending a message instead of answering, by steering or by promoting a follow-up into the running turn, declines the turn's pending questions, plugin dialogs, and MCP authorizations. A declined plugin dialog's plugin receives `false` for a confirmation and `null` for input or a choice.
- A question that isn't answered gives the model a `reason`: the user declined, sent a message instead, the turn ended first, or the question couldn't be answered.
- Shutting the server down no longer waits on a turn that is waiting for an answer.
- Question tools start running after the answer, not while the question waits, so a waiting question's tool row shows no spinner, and ACP clients see the tool call as `pending` rather than `in_progress` while it waits.
- `delete_session` plans again when the deletion runs: approving a child deletes its tree as it is then, and a session that left the tree is reported as not deleted. Calls it refuses before asking (for example, a busy child) now end with plain error text.

A fix before release made clients' answers to the model's confirm, input, and select questions go through; the first version refused them.

## Other changes

- **Comment boxes open where you comment.** In the terminal client, comments on selected text and on diagram parts open in a card at the selected words or the clicked part, below them or above when there's no room, instead of a centered dialog. Enter saves, Shift+Enter starts a line, and Escape or a click outside closes the card. Clicking a waiting comment's chip reopens the card to edit or delete the comment.
- **droids SDK:** a tool's optional `Declined` writes the result of a call the person didn't approve. `AskOptions.Requested` announces a live question as soon as it is recorded. `interaction.requested` and `interaction.settled` carry the interaction and its settlement as typed `InteractionRequested` and `InteractionSettled` events. `Promote` declines the turn's pending questions as steering does. A call whose before-tool policy changed while it waited for its answer runs the hook again under the new policy and keeps the answer. Stored answers are checked: a call that carries an answer droids couldn't have recorded is refused, and a stored approval must be exactly an answered yes. Interaction text rejects control characters other than newline and tab. Shutdown ends waits on a waiting turn with `ErrClosed`; the turn stays waiting for the next `Spawn`.
- **ADR 0073 rewritten:** droids is the unit applications compose, and conversation UI is shared between Kit's clients.
- **Project agents:** the repository adds a `user-tester` subagent and a `user-testing` skill for testing running clients as a user.

## Compatibility and limitations

The session protocol stays at 51; there is no wire break and no database migration. Kit 0.66.0 works with Kit 0.65.0 clients and servers, Kit for macOS 0.20.0 and newer, and the iOS TestFlight builds on protocol 51. The OpenAPI compatibility check against 0.65.0 reports no breaking changes. To pick up the new server, upgrade and restart it (`kit update`, or `brew update && brew upgrade akonwi/tap/kit` then `kit server restart`), and reload open browser tabs.

Kit for macOS 0.21.0 and later show files only with the download route, so against a 0.65.0 server their file tabs say the server needs an update; upgrade the server to 0.66.0. Older Kit for macOS releases and the iOS app still use the deprecated reads, which this server keeps serving ([#297](https://github.com/akonwi/kit/issues/297)).

**Plugin authors:** the plugin protocol doesn't change. A plugin dialog declined by steering now receives `false` or `null`. The TypeScript helper's `KIT_RELEASE` is `"0.66.0"`.

**Client and Go program authors:** update `github.com/akonwi/kit` to v0.66.0 for `DownloadFile` and `CheckFile`, and move off `readWorkspaceFile` and `readHostFile` before they are removed ([#298](https://github.com/akonwi/kit/issues/298)).

Known issues: declining an MCP authorization asks once more before the call fails. The terminal client shows at most 2 MiB and 65,536 lines of a file ([#294](https://github.com/akonwi/kit/issues/294)). Plugin command failures don't say why ([#241](https://github.com/akonwi/kit/issues/241)). Dismissing a subagent just as it finishes can leave its stored conversation until the server restarts ([#258](https://github.com/akonwi/kit/issues/258)). `kit update` treats `/dev/null` as a terminal and exits 0 instead of 2 ([#272](https://github.com/akonwi/kit/issues/272)). If one `kit update` has been downloading for over an hour, another `kit update` run in the same directory can remove its staged download ([#226](https://github.com/akonwi/kit/issues/226)). The terminal client can still panic while opening a session, in the background syntax highlighter ([#210](https://github.com/akonwi/kit/issues/210)). Subagent live streams still drop single events over 16 KiB until the subagent's transcript reloads ([#209](https://github.com/akonwi/kit/issues/209)), and one invalid event still fails every page of a subagent's live stream that holds it ([#208](https://github.com/akonwi/kit/issues/208)). Turn-end events still carry a generic failure reason for failures other than compaction ([#240](https://github.com/akonwi/kit/issues/240)). Diff file summaries never carry line counts ([#285](https://github.com/akonwi/kit/issues/285)). `kit server pair` lists the addresses from the server's settings rather than the ones it serves ([#222](https://github.com/akonwi/kit/issues/222)). The browser client does not work offline.

macOS CLI archives require macOS 14 or newer. Linux archives are built on Ubuntu 24.04 with a glibc 2.39 baseline and are not fully static. Windows and npm distribution are unsupported.
